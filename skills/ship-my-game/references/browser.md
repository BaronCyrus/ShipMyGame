# 准备浏览器

后台操作需要一个能读页面、点按钮、填表、运行页面 JavaScript 的浏览器工具。按下面顺序选第一个可用的，选定后写进进度档案。

## A. 用户自己的 Chrome（首选）

本仓库所有 `[实测]` 步骤都是在用户自己的 Chrome 里跑通的：用户平时就登录着 Google、微信公众平台、TapTap，一次登录的要求最容易满足。

| 你是 | 怎么接上用户的 Chrome |
|---|---|
| Claude Code / Claude 桌面版 | 用 Claude in Chrome 扩展（工具名 `mcp__claude-in-chrome__*`）。用户没装时：请他在 Chrome 应用商店安装「Claude」扩展并登录同一个 Claude 账号，然后重开会话。连着多个浏览器时，选标记为本机（onThisComputer）的那个。 |
| Codex、Cursor、Gemini CLI 等支持 MCP 的 agent | 用能接管用户现有 Chrome 的浏览器 MCP，例如 Playwright MCP 的扩展模式（`@playwright/mcp --extension`，配合 Chrome 里的「Playwright MCP Bridge」扩展），或按 Chrome DevTools MCP 官方文档连接到用户的 Chrome。如果所用工具只能另开一个独立的浏览器配置，就按 B 处理：用户在里面登录一次。 |

每次开工先列出用户的标签页，在**新标签页**里工作，不动用户已打开的页面。

上传文件：Claude in Chrome 的上传工具每次最多 10 MB；更大的文件、或藏在 shadow root 里的上传框，用 [uploads.md](uploads.md) 的「本机中转」法，这在 Chrome 里实测可用。

## B. 独立浏览器（Claude 桌面版内置浏览器、Playwright 自带浏览器等）

能用，但比 A 多两类人工：

- **要单独登录**：它的登录状态和用户的 Chrome 不通用，用户要在里面重新登录各个后台一次（之后会保留）。Google 对内嵌浏览器有额外检查，登录页能打开，但能否登录成功要用户实际试一次；被拒时换 A。
- **上传文件全靠用户手动**：2026-11-02 在 Claude 桌面版内置浏览器（Chromium 152）实测 `[实测]`：
  - 没有文件上传工具；
  - 页面向 `127.0.0.1` 发的 fetch 被浏览器直接拦截（`net::ERR_BLOCKED_BY_CLIENT`），iframe 同样被拦，所以「本机中转」法用不了；
  - 本机地址可以在地址栏直接打开，但 `window.open` 会替换当前标签页，后台页面会丢，无法用弹窗中转。
  
  所以每个文件都要用户拖进上传框（或在系统文件框里选）。你把文件准备好、放到桌面并在 Finder / 资源管理器里显示出来，告诉用户拖到哪个框。

  其余能力实测正常：打开 Play Console、微信公众平台、TapTap 开发者后台，读页面、点击、填表、执行页面 JavaScript。

文件多的环节（微信小游戏备案要十几张截图、TapTap 商店素材），建议换 A；也可以先看渠道 skill 里有没有官方 API / 命令行上传的方式。

## C. 没有浏览器工具

先帮用户装一个（见 A 的表格），装完重开会话。用户不想装时，改成「你说、他点」：

1. 你把所有要填的文字、图片、包体都准备好，放在 `publish/<渠道>/` 下，文字按字段整理成可直接复制的块。
2. 每次只给一小步：打开哪个网址 → 点哪个按钮 → 每个字段粘贴什么。
3. 请用户每步做完截图发给你，你核对后再给下一步。

## 所有方式都适用

- 读页面优先用读文字 / 读结构的工具，截图只在需要看布局时用。
- 后台的「下一步」「保存」可以直接点；**提审闸门**和本人事项按 [../SKILL.md](../SKILL.md) 的规则处理。
- 后台改版很常见：按钮名和 skill 不一致时，以页面为准，并记进进度档案的「与 skill 不符」。
