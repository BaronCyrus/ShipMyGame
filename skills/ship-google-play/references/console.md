# Play 管理中心：逐页怎么填

除另有标注外，本页都是 `[实测]`：2026-10 在个人账号上为两款游戏走通，界面为简体中文。左侧导航名称按 2026-11 核实的版本。后台改版时以页面为准，并把差异记进进度档案的「与 skill 不符」。

**网址规律**：`https://play.google.com/console/u/<n>/developers/<开发者ID>/app/<应用ID>/<页面>`。下文的 `页面 <x>` 指最后一段。`<开发者ID>`、`<应用ID>` 从当前网址里取，只记进进度档案，不写进任何公开文件。

**读页面**：`get_page_text` 在 Play 管理中心经常只返回侧栏。更可靠的做法是执行 `(document.querySelector('main')||document.body).innerText`，再用 `find` 取元素，截图只在需要坐标时用。

**保存规则**：几乎每个表单底部都有一句「保存后，更改会保存在“发布概览”中，供您送审」。保存的改动不会立刻生效，要和版本一起在「发布概览」里送审（见 [review.md](review.md)）。

## 1. 创建应用（「首页 → 创建应用」，页面 `create-new-app`）

| 字段 | 填法 |
|---|---|
| 应用名称（0/30） | 商店上显示的名称，以后可以改 |
| 软件包名称（0/150） | 和 Unity 的 applicationIdentifier 一致。**先点「检查可用性」**；第一次上传后就不能改 |
| 默认语言 | 默认是界面语言。面向海外时改成「英语（美国）- en-US」：下拉里找到 en-US，滚到可见位置再点 |
| 应用或游戏 | 游戏（以后可以在「商店设置」里改） |
| 免费或付费 | 按计划选。原文：「应用一旦发布，您便无法将免费应用更改为付费应用」 |
| 声明 | 「开发者计划政策」「美国出口法律」两个复选框，还有 Play 应用签名服务条款（[官方](https://support.google.com/googleplay/android-developer/answer/9859152?hl=zh-Hans)）。你讲要点，**用户勾选** |

- 点右下角「创建应用」，6～15 秒后跳到信息中心 `app-dashboard`。
- **点击后浏览器工具断线时不要重试**，否则会建出两个应用：先截图看按钮是否变灰、左下角是否在转圈，等它自己完成 `[实测-失败 → 已避免]`。
- 官方：免费游戏默认同时出现在 Google Play 和 Google Play Games 电脑版 [官方](https://support.google.com/googleplay/android-developer/answer/9859152?hl=zh-Hans)。实测首次提交时，系统自动加了一项「高级设置：已在“高级设置”中选择启用设备规格“Google Play 游戏电脑版”」。

## 2. 信息中心「完成游戏设置」的 11 项

信息中心 `app-dashboard` 有三块：
- 「立即快速分享您的游戏以进行初步质量检查」：内部测试，可选；
- 「完成游戏设置」：下面 11 项；
- 「发现游戏中的问题、获取反馈并解锁正式版发布权限」：封闭测试，做完设置才解锁。

11 项按界面顺序：设置隐私权政策、登录详细信息、广告、内容分级、目标受众群体、数据安全、政府应用、金融产品和服务、健康、选择应用类别并提供详细联系信息、设置商品详情。每一项都可以从信息中心点进去，也可以直接打开对应的 `app-content/...` 页面。11 项全部完成后，「完成游戏设置」整块会从信息中心消失。

**「广告 ID」不在这 11 项里**，但不填就不能送审，见第 3 节。

### 2.1 隐私权政策
- 只有「隐私权政策网址」一个字段：填公开的 https 页面（模板 `templates/privacy-policy.en.html`），先用 `curl -s -o /dev/null -w "%{http_code}" <网址>` 确认返回 200。
- 官方要求：网页公开、全球可访问、不用登录、不能是 PDF，内容针对本应用 [官方](https://support.google.com/googleplay/android-developer/answer/9859455)。应用内也要放这个链接。
- **底栏「保存」左边紧挨着「舍弃」**。误点会弹「要舍弃更改吗？」，点「取消」后输入框也会被清空，只能重填。要点最右边的蓝色「保存」，看到左下角提示「更改已保存」才算成功 `[实测-失败 → 已修复]`。

### 2.2 登录详细信息（页面 `app-content/testing-credentials`）
- 「应用是否有部分内容设有访问限制」：没有登录墙时选「否」，即所有功能都不需要特殊权限。
- 游戏需要登录时：选「是」，给审核员提供可用的测试账号，最多 5 组说明 [官方](https://support.google.com/googleplay/android-developer/answer/9859455)。

### 2.3 广告（页面 `app-content/ads-declaration`）
- 「您的应用是否包含广告？」：集成了广告 SDK 就选「是」，封闭测试期用测试广告也选「是」。商店页会显示「含广告」。

### 2.4 内容分级（页面 `app-content/content-rating-overview` →「开始填写调查问卷」）
三步：「1 类别 → 2 调查问卷 → 3 摘要」。

1. **类别**：
   - 「邮箱」：IARC 联系邮箱，填用户指定的邮箱；
   - 「类别」：选「游戏」；
   - 「条款及条件」：「我同意国际年龄分级联盟 (IARC) 颁发的《使用条款》」，你讲要点，**用户勾选**；
   - 然后点「下一步」。
2. **调查问卷**：按游戏实际内容逐题回答。实测的益智游戏全部答「否」，分组有：暴力、恐怖、性、赌博、语言、受管制物品、粗俗幽默、数字购买、其他。还有这些单独的题：用户之间能否互动（语音、文字、分享图片或音频）、是否共享精确位置、纳粹符号、损害大韩民国国家认同的内容、恐怖活动、犯罪手段的现实描述。
   - 问卷是手风琴结构，批量点击只对已展开的组生效 `[实测-失败]`。用第 8 节的脚本按组作答，再**逐题读题干核对**。
3. **先点底栏「保存」，「下一步」才会变成可点**。然后进「摘要」，再点「保存」。
   - 实测结果：「适合所有人」，ESRB E、PEGI 3、澳大利亚 G、巴西 L。
   - 不填会显示「未分级」，可能被下架 [官方](https://support.google.com/googleplay/android-developer/answer/9898843)。

### 2.5 目标受众群体和内容（页面 `app-content/target-audience-content`）
- 共五步。「您的应用适合哪些目标年龄段的用户?」选项有：5 周岁及以下、6-8、9-12、13-15、16-17、年满 18 周岁。
- 不面向儿童的游戏：**只勾 13-15、16-17、年满 18**。点「下一步」后会直接跳到第 5 步「摘要」，再点「保存」。
- 只要选了 13 岁以下的任一年龄段，就要遵守「家庭」政策：只能用家庭自认证的广告 SDK，不能传输广告 ID 等 [官方](https://support.google.com/googleplay/android-developer/answer/9893335)。商店素材也不要有明显吸引儿童的风格。

### 2.6 数据安全（页面 `app-content/data-privacy-security`）
共五步：「1 概览 → 2 数据收集和安全性 → 3 数据类型 → 4 数据使用和处理 → 5 预览」。第一次进入会先弹 3 页介绍，连点「下一步」关掉。右上角有「导出为 CSV 文件 / 从 CSV 文件导入」，第二款游戏答案相同时可以复用（未实测）。

规则 [官方](https://support.google.com/googleplay/android-developer/answer/10787469)：
- 封闭测试、开放测试、正式版都必须填；只在内部测试轨道的应用可以不填。
- 第三方 SDK 收集的数据也要申报。

**第 2 步**（下表按「只接 AdMob 广告、没有自建账号和服务器」的游戏）：

| 题目（界面原文） | 选择 |
|---|---|
| 您的应用是否会收集或分享任何必须披露的用户数据类型? | 是 |
| 您的应用收集的所有用户数据在传输过程中是否会加密? | 是 |
| 您的应用支持以下哪些账号创建方法? | 我的应用不允许用户创建账号 |
| 用户是否可以使用在应用之外创建的账号登录您的应用? | 只有广告时选「否」。**接了 PGS 后选「是」**，追问「这些账号是如何创建的」选「其他」，说明填 `Optional sign-in with a Google Play Games account, created in Google Play Games outside the app` |
| 您是否为用户提供了请求删除其数据的方法？（选答） | 实测留空 |

**第 3 步数据类型**：每个分类要先点「显示内容：…」展开。AdMob 部分按 [官方 AdMob 数据披露页](https://developers.google.com/admob/android/privacy/play-data-disclosure) 勾选：GMA SDK 会自动收集 IP 地址、用户产品互动、诊断信息、设备和账号标识符。

| 分类 | 勾选 |
|---|---|
| 位置 | 大致位置信息 |
| 应用活动 | 应用互动 |
| 应用信息和性能 | 诊断信息（另一款还勾了「崩溃日志」） |
| 设备或其他 ID | 设备 ID 或其他 ID |
| 个人信息（**接 PGS 后加**） | 名称、用户 ID |
| 应用活动（**接 PGS 后加**） | 其他操作（成就和分数） |

**第 4 步数据使用和处理**：每种数据点「开始」，在对话框里选：

| 数据 | 收集 | 分享 | 临时处理 | 必需 / 可选 | 用途（「为什么收集」和「为什么分享」都勾） |
|---|---|---|---|---|---|
| AdMob 的 4～5 项 | ✓ | ✓ | 否 | 必须收集 | 「分析」「广告或营销」「欺诈防范、安全和法规遵从」 |
| 名称、用户 ID、其他操作（PGS） | ✓ | ✗ | 否 | 用户可选 | 「应用功能」 |

- 对话框里的选项按**文字精确匹配**来点（第 8 节的思路），每填完一项都读回全部勾选状态核对，再点对话框里**最后一个可见的「保存」**。
- 「保存」和「保存为草稿」是两个按钮，要区分开。
- 页面有时会横向滚动，导致坐标点错。把所有元素的 `scrollLeft` 置 0 就好。
- PGS 一侧的申报是按保守方式选的；PGS 官方数据说明见 [官方](https://developer.android.com/games/pgs/data-collection)。
- 第 5 步「预览」核对后保存。会弹「要前往“发布概览”吗？」，选「以后再说」，等版本一起送审。

### 2.7 政府应用 / 金融产品和服务 / 健康

## 3. 「应用内容」页：清空所有「开始声明」

打开 `app-content/overview`（左侧导航「监控和改进 → 政策和计划 → 应用内容」），把「需要处理 / 需要注意」里的每一项都处理掉。

- **广告 ID**（页面 `app-content/ad-id-declaration`）：
  - 页面原文：「您必须先完成此部分，然后才能提交以 Android 13 为目标平台的版本」。
  - 「您的应用是否使用了广告 ID？」选「是」（GMA SDK 会自动带上 `AD_ID` 权限，[官方](https://support.google.com/googleplay/android-developer/answer/6048248)）。
  - 用途勾「分析」「广告或营销」「欺诈防范、安全和法规遵从」→ 保存。
  - 第二款游戏漏了这一项，送审前的快速检查报「“广告 ID”声明不完整」，送不了审 `[实测-失败 → 已修复]`。按 ref 勾选时还勾错过一次，把「分析」勾成了「应用功能」。所以一定要读回勾选状态。
- **交易者身份**：账号声明为交易者时，要在这里逐个应用确认 [官方](https://support.google.com/googleplay/android-developer/answer/17594752?hl=zh-Hans)。这一项本仓库未实测。
- 其他声明（敏感权限、照片和视频、新闻等）：按页面提示如实填写。用不到的敏感权限从工程里删掉，见 [build.md](build.md)。

## 4. 商店设置（左侧导航「商店发布 → 商店设置」，页面 `store-settings`）

- **应用类别**：点「修改」→「应用或游戏」选游戏 →「类别」17 选 1（休闲、体育、冒险、动作、卡牌、教育、文字游戏、桌面和棋类游戏、模拟、益智、知识问答、竞速、策略、街机、角色扮演、赌场、音乐）→ 保存。下拉选项不在可访问性树里：读 `[role=option]` 的文字，再用 JS 点击。
- **标签**：「管理标签」，**最多 5 个**。对话框里有搜索框，先搜索再点，最后读回已选的行核对。用 find 返回的 ref 点表格行时选错过一次（选成了无关标签）`[实测-失败 → 已修复]`。
- **商品详情中的详细联系信息**（原文「这些信息会在 Google Play 上向用户显示」）：
  - 邮箱：必填，填用户指定的公开邮箱；
  - 电话：选填；
  - 网站：填开发者网站。要接 AdMob 时，**这个网站的域名就是 app-ads.txt 所在的域名**，见 [capabilities.md](capabilities.md) 第 2.6 节。

## 5. 封闭测试（左侧导航「测试和发布 → 测试 → 封闭式测试」）

信息中心「发现游戏中的问题、获取反馈并解锁正式版发布权限」展开后有 5 个任务：选择国家和地区 → 选择测试人员 → 创建新的发布版本 → 预览并确认此发布版本 → 将此发布版本送交 Google 审核。默认轨道名是「封闭式测试 - Alpha」，页面是 `tracks/<轨道ID>`。

1. **国家/地区**：点「添加国家/地区」→「全选」→ 保存。实测显示 178 个国家/地区；同一次提交还自动带上了「取消与正式版轨道的同步」「恢复轨道」。
2. **测试人员**（`?tab=testers`）：说明原文「您可以通过电子邮件收件人列表或 Google 群组选择测试人员」，两种方式**只能选一种**。
   - **Google 群组（推荐）**：填群组邮箱后会变成标签，可以连续加多个群组。一个群组可以给多个应用用，但测试者要对每个应用分别加入、分别安装。
   - **电子邮件列表**：「创建电子邮件列表」→「列表名称」+ 邮箱（逗号分隔、回车确认，也可以上传 CSV，不能带 UTF-8 BOM）→「保存更改」→「确认」。官方上限：每个列表 2000 人，每个轨道 50 个列表 [官方](https://support.google.com/googleplay/android-developer/answer/9845334?hl=zh-Hans)。
   - **从邮件列表切到群组后，原列表里的人不再算测试者**。群组所有者自动是成员，用户的其他账号要手动加入群组 `[实测]`。
   - 「接收反馈的网址或电子邮件地址」（上限 512 字符）：填用户指定的邮箱 → 保存。
   - 建群组的步骤见 [review.md](review.md) 第 2 节。
3. **创建发布版本**（页面 `tracks/<轨道ID>/releases/<n>/prepare`，标题「创建封闭式测试版本」）：
   - 先填「发布版本名称」和「版本说明」，点「保存为草稿」。
   - 版本说明用语言标签包住，每种语言 ≤500 字符，最多 20 种语言，可以「从先前发布版本复制」：
     ```
     <en-US>
     First release.
     </en-US>
     <zh-CN>
     首个版本。
     </zh-CN>
     ```
   - 再请用户把 AAB 拖进「将 app bundle 拖放至此处即可上传」的方框，做法见 [uploads.md](../../ship-my-game/references/uploads.md) 第 4 节。上传后显示「您的 xxx.aab 上传要进行优化再分发…」，约 20 秒后版本表出现「2 (1.0.1)」这样的条目。用第 8 节的脚本等待，**不要刷新页面**，否则会丢掉没保存的改动。
   - 第二个及以后的版本：「上一版本」默认「不包含」旧 bundle，保持不包含。
4. 点「下一步」进入预览页 `releases/<n>/review`：
   - 有问题时显示「我们发现您的版本存在一些问题」，点「展开验证详情」读全文。这些「提醒」不挡送审：去混淆文件、原生调试符号（脚本已处理）、设备支持范围变化（「不再支持的设备 / 新支持的设备」都为 0 就可以忽略）。
   - 「版本分发」显示新安装大小和下载用时。
5. 点底栏「保存」→ 弹「要前往“发布概览”吗？」→「转到概览页面」。

## 6. 发布概览（页面 `publishing`）

- 顶部是「自管式发布模式」开关。实测保持关闭（原文「如果自管式发布模式已关闭，更改将在获得批准后立即发布」），过审后自动推给测试者。
- 第一次进入有三页新手引导，`Escape` 不一定能关，点三次「下一步」。
- 「尚未提交送审的更改」区列出每项改动，并在跑「正在快速检查常见问题…至多还需 14 分钟」。报问题时显示「查看 N 个问题」，必须先修。快速检查还没跑完也可以先提交，检查通过后会自动送审。
- 提交和后续处理见 [review.md](review.md)。

## 7. 应用签名页：读证书指纹（页面 `keymanagement`）

左侧导航路径以帮助中心为准：「由 Google Play 提供保护 → Play 商店保护 → 管理 Play 应用签名」[官方](https://support.google.com/googleplay/android-developer/answer/9842756?hl=zh-Hans)。上传过第一个 AAB 才会有应用签名密钥。

- 实测页面上的块：
  - 「应用签名密钥 — 正在使用 / 更改密钥 / 下载证书 / SHA-256 证书指纹 / SHA-1 证书指纹」；
  - 「之前的应用签名密钥 — 首次使用日期 … 量子就绪（Beta 版）」；
  - 「上传密钥 — 请求重置 / 下载证书 / 指纹」；
  - 「Digital Asset Links JSON 文件」。
- **指纹在页面里是隐藏的**，只有点「复制」才写进剪贴板。先在页面里接管剪贴板（[uploads.md](../../ship-my-game/references/uploads.md) 末节），实测还要同时接管 `document.execCommand('copy')`：
  ```js
  window.__copied = [];
  navigator.clipboard.writeText = async t => { window.__copied.push(t); };
  const oe = document.execCommand.bind(document);
  document.execCommand = (c, ...a) => { if (c === 'copy') window.__copied.push(String(document.getSelection())); return oe(c, ...a); };
  // 再点 aria-label 为「Copy SHA-1 证书指纹 to clipboard」的按钮，或「复制所有证书指纹」，然后读 window.__copied
  ```
- 页面上用正则能匹配到的那串十六进制，是 Digital Asset Links JSON 里的 SHA-256 片段，**不是 SHA-1**。
- 「复制所有证书指纹」会一次给出多个 SHA-1，包括量子就绪密钥的两个。它们怎么用见 [capabilities.md](capabilities.md) 第 1.3 节。
- 指纹只用来建凭据，不写进进度档案以外的任何文件。

## 8. 页面脚本（都已实测）

**给输入框赋值**：Angular 表单不认直接赋的 value。

```js
const setv = (el, v) => {
  const proto = el.tagName === 'TEXTAREA' ? HTMLTextAreaElement.prototype : HTMLInputElement.prototype;
  Object.getOwnPropertyDescriptor(proto, 'value').set.call(el, v);
  ['input', 'change', 'blur'].forEach(t => el.dispatchEvent(new Event(t, { bubbles: true })));
};
// 赋值后读页面上 /^\d+\/\d+$/ 形式的计数器（如 28/30），确认框架已识别
```

**手风琴单选问卷**：每组选「否」，再逐题核对。

```js
const g = {};
document.querySelectorAll('input[type=radio]').forEach(r => (g[r.name] = g[r.name] || []).push(r));
for (const rs of Object.values(g)) if (!rs.some(r => r.checked) && rs.length === 2) rs[1].click();   // 实测第 2 个是「否」
// 核对：从每组第一个 radio 往上找第一个 innerText 长度 > 25 的祖先元素，那就是题干；逐题确认答「否」符合游戏实际
```

**等用户拖完 AAB**：轮询，不刷新页面。

```js
(async () => {
  for (let i = 0; i < 18; i++) {                       // 最多等 90 秒，没好就过一会儿再调用一次
    await new Promise(r => setTimeout(r, 5000));
    const t = document.body.innerText;
    if (/\d+ \(\d+\.\d+\.\d+\)/.test(t) && !/上传要进行优化再分发/.test(t)) return 'done';
  }
  return 'waiting';
})()
```

**找底栏按钮**：底栏常见「舍弃更改 / 保存为草稿 / 返回 / 保存 / 下一步」，位置不固定。用 `[...document.querySelectorAll('button')].filter(b => b.innerText.trim() === '保存' && b.offsetParent).pop()` 取最后一个可见的「保存」。

**加入链接、ID**：复制按钮的 aria-label 里就有完整链接（「复制链接：https://…」），遍历元素属性就能找到。应用 ID 等从网址里取。

**上传框**：不要点「上传」按钮，也不要触发 file input 的 click，那会弹出系统文件框、冻住标签页。做法见 [listing.md](listing.md) 第 3 节。
