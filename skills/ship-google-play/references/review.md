# 送审、测试者、正式版

## 1. 封闭测试送审（第一次提审闸门）`[实测]`

**前提**（全部满足再走提审闸门）：
- 信息中心的「完成游戏设置」11 项已经消失；「应用内容」里没有待处理的声明，**广告 ID 必须已填**。
- 封闭测试轨道已设置国家/地区和测试人员，版本已「保存」到发布概览（[console.md](console.md) 第 5 节）。
- AAB 自检通过（[build.md](build.md) 第 4 节）：targetSdk 36、16 KB、测试广告 ID。
- 隐私政策网址返回 200。

**步骤**：
1. 打开「发布概览」，读「尚未提交送审的更改」：
   - 核对改动项和数量。实测首发一次是 16 项，加上 19 份译文那次是 35 项。
   - 等「正在快速检查常见问题」跑完，最多约 14 分钟。报「查看 N 个问题」时先修。
2. 按[提审闸门](../../ship-my-game/SKILL.md)列给用户：
   - 轨道（封闭测试）、版本「versionCode (versionName)」、国家/地区数量、测试人员方式；
   - 商店文案要点、广告和数据安全声明；
   - 预计时长：实测 10～42 分钟，官方说「通常会在 7 天内完成」。
3. 用户说「提交」后，点「提交 N 项更改以供审核」→ 确认框「要将 N 项更改送审吗？…」→「将更改内容送审」。
   - 实测：用户在当轮对话里明确说过要提交时，agent 能点；当轮用户只提了别的需求时，agent 的点击被权限系统拦下 `[实测-失败]`。被拦就把页面停在这个按钮上，请用户点。
4. 读页面，确认那一区变成「正在审核中的更改：…您的更改目前正在接受审核」。记录提交时间。

**实测审核时长**：有确切时间的 7 次送审都在 **10～42 分钟**内通过，包括首发和普通更新；两款游戏都没被拒过 `[实测]`。官方说审核可能长达 7 天甚至更久，新账号可能需要更长时间 [官方](https://support.google.com/googleplay/android-developer/answer/9859751?hl=zh-Hans)。

完成标准：发布概览显示「正在审核中的更改」；进度档案记下提交时间、预计时长，以及去「发布概览」看结果。

## 2. 过审之后：加入链接和测试者 `[实测]`

1. **加入链接**：打开封闭测试轨道的「测试人员」标签页，找两个复制按钮：「在 Android 设备上参与测试」和「在网页中参与测试」。完整链接写在按钮的 aria-label 里。
   - 加入链接形如 `https://play.google.com/apps/testing/<包名>`，商店页形如 `https://play.google.com/store/apps/details?id=<包名>`。
   - 发布前这里只显示「您的应用一经发布，链接就会显示在此处」。
   - 官方说首次发布后链接可能要几个小时才对测试者生效 [官方](https://support.google.com/googleplay/android-developer/answer/9845334?hl=zh-Hans)。实测首版过审后马上能读到链接，约 2.5 小时后用户的第二个账号成功加入并安装。
2. **Google 群组**（groups.google.com →「创建群组」）：
   - 第 1/3 步：填群组名称、群组邮箱前缀、简介。
   - 第 2/3 步「隐私设置」：谁可以搜索群组 =「网络上的任何人」；谁可以加入群组 =「网络上的任何人都可以加入」；发帖和查看成员只限管理员。
   - 第 3/3 步：成员留空，点「创建群组」。
   - **最后的人机验证只能由用户点**。建好后读设置页的单选状态核对，再把群组邮箱挂到封闭测试轨道，然后送审（只改测试人员也要送审）。
3. **招募**：用 `templates/testers-recruitment.md` 写中英文文案。
   - 亲友版：加群组 → 用同一个账号点「成为测试者」→ 从 Play 安装，保持安装至少 14 天。
   - 社区版：r/TestersCommunity、r/AndroidClosedTesting 等互测版块。浏览器扩展打不开 reddit.com，帖子由你写、**用户发**。互测时用户要用自己手机上的账号加入别人的测试，并保留 14 天。
   - 有的社区自带公共 Google 群组，地址在发帖页右侧栏，发完帖就看不到了。很多人的测试只对这个群组开放，把它也挂进自己的轨道。
   - 测试期间一律用测试广告 ID：互测的人可能会「帮忙」点广告，这会被判为无效流量。
4. **数人数**：看信息中心「申请正式版发布权限」卡片。原文「目前有 N 名测试人员已持续参与 M 天」`[实测：卡片原文]`。
   - 实测进度：上线约 24 小时后有 9 人。其中一款在封闭测试上线 16 天后查看时，三项条件都已满足（哪一天满足的没有记录）。招 15～20 人留余量。
   - 实测参与度：多数测试者只在头两天玩，之后每天约 1 人打开，日活/月活在 5%～20%。官方把参与度不够列为被要求继续测试的原因之一，这样的参与度能不能获批，等结果出来再补。
   - 中途退出的人不计数，重新加入要重新连续满 14 天 [官方](https://support.google.com/googleplay/android-developer/answer/14151465?hl=zh-Hans)。
5. **反馈**：在「监控和改进 → 评分和评价 → 测试反馈」查看，把有用的反馈和对应修复记进进度档案。申请正式版时要总结这些反馈 [官方](https://support.google.com/googleplay/android-developer/answer/14151465?hl=zh-Hans)。

## 3. 发更新

- versionCode 加 1 → 构建 → 自检 → 上传。上传可以由用户拖进新版本，也可以用 API，见 [automation.md](automation.md) → 版本说明 → 保存 → 发布概览 → 提审闸门。
- **改动攒齐一次提交**：已有改动在审核时再提交，会弹「要重新发送审核申请吗？您已有一项审核正在进行中…如果现在发送此变更，系统会取消当前审核进程并重新开始审核，这会增加您的等待时间」`[实测]`。同一轨道上再保存新版本，会替换正在审核的那个版本（推断，和这个弹窗一致）。
- 只改测试人员、只改商品详情也要送审 `[实测]`。
- 改了数据安全申报（例如接了 PGS），隐私政策也要在审核结束前更新上线，见 [capabilities.md](capabilities.md)。
- 实测更新同样 10～42 分钟过审，过审后自动推送给测试者（自管式发布保持关闭）。

## 4. 送审被拦、被拒

**快速检查报问题**（送审前）：发布概览里「查看 N 个问题」。实测原文：

```
发现了 1 个问题
我们发现了一些常见问题，导致您的应用无法送审。您必须先解决这些问题，然后才能将更改送审。
“广告 ID”声明不完整
所有以 Android 13 或更高版本为目标平台的开发者，都必须告诉我们其应用是否使用了广告 ID
```

修法：「应用内容 → 广告 ID」填好后回到发布概览，确认不再报问题 `[实测-失败 → 已修复]`。

发布前检查的规则 [官方](https://support.google.com/googleplay/android-developer/answer/14807773?hl=zh-Hans)：
- 关键问题必须先修；其余问题可以点「仍然继续」并选择原因（「我已计划解决此问题」「此问题为误报」等）。
- 检查最多 15 分钟。没跑完也可以点「送审」，检查通过后会自动提交。
- 通过检查不等于通过正式审核。

**更新被拒 / 应用被拒**（审核后）[官方](https://support.google.com/googleplay/android-developer/answer/9859751?hl=zh-Hans)：
- 「应用被拒」只出现在首次发布的草稿应用上；「更新被拒」是之后的更新被拒。
- 处理：读邮件和「政策状态」页里的原因 → 修改 → 重新提交，或者申诉。**不要原样重提**。
- 被拒之后，新改动**不会自动送审**，要在「发布概览」里手动点「送审」[官方](https://support.google.com/googleplay/android-developer/answer/9859654?hl=zh-Hans)。用 API 提交时要带 `changesNotSentForReview=true`，见 [automation.md](automation.md)。
- 本仓库的实测游戏没有被拒过，以上处理步骤只有官方依据。

## 5. 申请正式版（提审闸门）

**条件**（2023-11-13 之后注册的个人账号）：封闭测试至少 12 名测试人员连续 opt-in 满 14 天。满足前，「测试和发布 → 正式版」和「预注册」都不可用 [官方](https://support.google.com/googleplay/android-developer/answer/14151465?hl=zh-Hans)。

**信息中心卡片**（`[实测]`，2026-11 核实）：
```
正式版 | 申请正式版发布权限
正式版是指通过 Google Play 面向数十亿用户发布游戏。您需要先运行符合我们的条件的封闭式测试，然后才能申请正式版发布权限。
在申请时，您还需要回答一些与封闭式测试相关的问题。 预览问题
✓ 发布封闭式测试版本
✓ 招募至少 12 名测试人员参与您的封闭式测试
□ 招募至少 12 名测试人员参与您的封闭式测试至少 14 天 — 目前有 N 名测试人员已持续参与 M 天
[申请发布正式版]
```

三项都满足后，三行都打勾，「目前有 N 名…」那句不再显示，按钮旁边是「了解详情」链接 `[实测]`。

**问卷**（`[实测]`，2026-11 提交过一次）：点「申请发布正式版」弹出「申请正式版发布权限」对话框，分三步：
1. 关于您的封闭式测试：4 题，比帮助页多一道「怎么招募测试人员」；
2. 关于您的游戏（不公开）：3 题；
3. 您的正式版就绪情况：2 题。

每道文字题最多 300 个字符。前两步点「下一步」才会保存，最后一步点「应用」提交（帮助页译作「申请」）。题目原文、选项和要查的数据见 `templates/production-access-answers.md`。

用这个模板起草，用户确认后走提审闸门，再点「应用」。提交成功时左下角提示「申请已提交」，卡片变成「我们已收到您的正式版发布权限申请」并写着提交时间。审核结果还没出，出来后补到这里。

**申请不会送审「发布概览」里的更改**：实测提交申请后，信息中心的更新状态仍是「尚未送审」。那些更改要另外送审，或者跟正式版一起送审 `[实测]`。

**结果**：通常 7 天内，邮件发给账号所有者。被要求继续测试的常见原因：opt-in 不足 12 人，或测试期间参与度不够。批准后会开放「正式版」和「开放式测试」[官方](https://support.google.com/googleplay/android-developer/answer/14151465?hl=zh-Hans)。

## 6. 发布正式版（提审闸门）

除了第 1 步的打包和核对，以下步骤本仓库未实测，只有官方依据。

1. 换正式广告 ID，可以在等申请结果时先做：
   - 在 `ShipAds.cs` 里填正式广告单元 ID，在 GoogleMobileAdsSettings 里换成正式 App ID → versionCode 加 1 → 构建。
   - 用 bundletool 读清单，确认 `APPLICATION_ID` 是正式 ID、包里没有测试 App ID、带 `AD_ID` 权限。实测在等结果期间打好了包，并这样核对过 `[实测]`。
   - 这个包只发正式版，不要传到封闭测试轨道：测试期一律用测试广告（第 2 节）。
2. 先发布 PGS 配置，至少 2 小时后再上线游戏，见 [capabilities.md](capabilities.md) 第 1.9 节 [官方](https://developer.android.com/games/pgs/console/publish)。
3. 「测试和发布 → 正式版」→ 国家/地区 →「创建新的发布版本」→ 上传或从内容库添加 AAB → 版本说明 →「下一步」→ 预览 →「保存」[官方](https://support.google.com/googleplay/android-developer/answer/9859348?hl=zh-Hans)。首个正式版没有分阶段发布百分比可选。
4. 发布概览 → 提审闸门 → 送审。「尚未提交送审的更改」里之前攒下的改动（例如交易者身份声明）会一起送审，逐项列给用户。审核通过后，正式版面向所选国家/地区的所有用户（自管式发布关闭时自动上线）。
5. 上线后：在 AdMob 里关联商店并完成 app-ads.txt 验证（[capabilities.md](capabilities.md) 第 2.7 节）；自己的设备上不要点正式广告。
6. 封闭测试的测试人员也会收到正式版：正式版的版本代码比测试轨道高时，加入测试的用户会收到正式版 [官方](https://support.google.com/googleplay/android-developer/answer/9845334?hl=zh-Hans)，也就会看到真实广告。暂停封闭测试轨道挡不住这一点：暂停后测试人员只是不再收到测试轨道的更新，应用仍留在设备上 [官方](https://support.google.com/googleplay/android-developer/answer/9845334?hl=zh-Hans)。

## 7. 时长参考

| 事项 | 时长 | 依据 |
|---|---|---|
| 封闭测试送审到过审 | 10～42 分钟（n=7） | `[实测]` |
| 应用审核（官方说法） | 通常 7 天内，个别更久；新账号可能更久 | [官方](https://support.google.com/googleplay/android-developer/answer/9859751?hl=zh-Hans) |
| 发送前快速检查 | 最多约 14～15 分钟 | `[实测]`、[官方](https://support.google.com/googleplay/android-developer/answer/14807773?hl=zh-Hans) |
| 正式版权限申请审核 | 通常 7 天内 | [官方](https://support.google.com/googleplay/android-developer/answer/14151465?hl=zh-Hans) |
| 测试人员凑满 12 人 × 14 天 | 至少 14 天。实测 2 天内只到 9 人；一款游戏在封闭测试上线 16 天后查看时三项都已满足 | `[实测]` |
| 等用户拖 AAB | 用户在电脑前约 50 分钟，不在时 12～15 小时 | `[实测]` |
