# 提审、审核结果和版本更新

本文对应 SKILL.md 的 P7。实测的那次发布到提审之前就停了，所以本文的提交步骤只有官方文档和页面原文作依据。走的时候要更仔细地读页面，和本文不一致时以页面为准，并记进进度档案的「与 skill 不符」。

## 1. 提审前逐项核对

| # | 检查项 | 在哪看 |
|---|---|---|
| 1 | 要提审的开发版本，「包体准入测试」显示通过（安卓至少 4/5），用户已经在真机上扫码玩过 | 小游戏管理 → 包体管理 |
| 2 | 前置备案已通过。正式上架必须有它 [官方](https://developer.taptap.cn/minigameapidoc/quick-start/guide/pre-filing/)；备案没通过时页面是否允许提交，未确认 | 小游戏管理 → 小游戏资质 |
| 3 | 隐私保护指引已提交，并且和「小游戏隐私设置」、游戏内隐私政策三者一致 | 基础配置；商店资料 → 隐私说明 |
| 4 | 商店资料所有必填项已填，素材符合 [listing.md](listing.md) | 商店 → 版本管理 → 未发布版本 |
| 5 | 接了成就的：已点「发布普通成就」（至少 5 个） [官方](https://developer.taptap.cn/docs/sdk/achievement/features/) | 游戏服务 → 运营工具 → 成就 |
| 6 | 接了排行榜的：已关掉「仅白名单可见」，测试数据已清空，客户端里的排行榜 ID 正确 [官方](https://developer.taptap.cn/docs/sdk/leaderboard/features/) | 游戏服务 → 运营工具 → 排行榜 |
| 7 | 游戏内合规：同意弹窗、启动页适龄标识和隐私按钮、适龄提示、TapTap 登录、没有点了没反应的广告按钮 | 真机扫码确认 |
| 8 | 游戏名一致：游戏内名称（`productName`）和商店游戏名一致 | 审核规范 3.6.4 |

## 2. 怎么提交

**页面上的机制**（2026-11-02 读到的原文）`[实测：页面原文]`：在商店资料的「游戏下载和获取 → TapTap 小游戏 → 请选择已上传的小游戏包体」里，「若选择未过审包体，提交游戏资料后，将会自动提审对应包体」。也就是说，**选包体加提交商店资料，就是一次完整的提审**，不用另外给包体提审。

步骤：
1. 在「游戏下载和获取」里点选择包体，在弹窗「选择已上传的历史包体，单选」里选通过准入测试、状态为「未提审」的版本，点「确认」`[实测：弹窗]`。
2. Android 游戏状态选「开放试玩」，iOS 选「敬请期待」或「预约」`[实测]`。
3. 在页面底部的「发布设置」里选「立即上线」或「定时上线」。新游戏第一次定时，时间必须在当前时间 6 小时以后；审核通过后可以改成之后的任意时间 [官方](https://developer.taptap.cn/minigameapidoc/quick-start/guide/creation-improvement/)。
4. **提审闸门**：按 [ship-my-game 的规则](../../ship-my-game/SKILL.md)，把下面这些列给用户，等他说「提交」：
   - 渠道：TapTap 小游戏；
   - 包体版本号（V x.y.z）和准入测试结果；商店版本名称（V-<日期>）；
   - Android「开放试玩」/ iOS 状态；
   - 游戏名、简介要点、首页推荐语、适龄分级；
   - 小游戏隐私设置的选项、隐私政策链接、隐私保护指引的状态；
   - 有没有广告、是否提供 AI 合成服务；
   - 发布设置（立即或定时）；
   - 预计 1～3 天出结果，结果在「版本审核记录」和消息中心看。
5. 用户说「提交」后，点「下一步」，在后面的页面点「提交审核」[官方](https://developer.taptap.cn/minigameapidoc/quick-start/guide/game-publish/version/)。「下一步」之后的页面长什么样，本仓库还没见过，以页面为准。被权限系统拦下时，停在按钮上请用户点。同类的「提交」按钮实测被拦过。
6. 读页面确认版本状态变成「审核中」，再更新进度档案。

**官方文档里的另一条入口** [官方](https://developer.taptap.cn/minigameapidoc/quick-start/guide/game-publish/version/)：
1. 包体管理 → 开发版本，在要上线的版本上点「提审」，商店资料里会自动生成一个「未发布版本」。
2. 补全资料后点「下一步」。
3. 选 Android 游戏状态：文档写的是「正式上线」，没有版号时实际只能选「开放试玩」。
4. 选发布设置，点「提交审核」。

两条入口最后的效果一样，用哪条都行。

**用 CLI 提审**：先用 `taptap-cli app prepare-review-snapshot` 和 `precheck-app-review` 做预检，把结果给用户看，用户说「提交」后再执行 `submit-app-review --yes`，见 [automation.md](automation.md)。这条路本仓库还没实测。

## 3. 审核时长和状态

审核时长 [官方](https://developer.taptap.cn/minigameapidoc/quick-start/guide/creation-improvement/)：
- 新游戏第一次提审，资料合规时预计 1～3 天。
- 用「+新版本」更新，预计 1 天内。
- 资质审核不支持定时，要提前提交。

各状态能做的操作 [官方](https://developer.taptap.cn/minigameapidoc/quick-start/guide/game-publish/version/)：

| 状态 | 能做什么 |
|---|---|
| 未发布 | 编辑资料、提交审核、删除 |
| 审核中 | 只能查看；可以「撤销审核」，撤销后回到未发布 |
| 审核失败 | 查看失败原因，修改后再提交 |
| 定时上线 | 只能查看；可以改上线时间，或撤销定时（撤销后变成审核失败状态） |
| 已上线 / 已下架 | 只能查看；可以构建新版本 |

审核中的包体在「包体管理 → 审核版本」里看。结果在「商店 → 资质与审核 → 版本审核记录」和「消息中心」里看 `[实测：页面存在]`。

进度档案的「等待中」要写：提交日期、预计结束日期（加 3 天）、查看位置。到期还没结果，先去这两个地方看。

## 4. 被驳回怎么办

1. 在「版本审核记录」里读驳回原因的原文，记进进度档案。
2. 对照条文改。常见的几类：
   - **素材**：截图里有手机界面或平台界面、宣传图有游戏名以外的文字或用了图标、录屏前 5 秒没有玩法。按 [listing.md](listing.md) 第 9 节对照。
   - **名称**：游戏名带了无关词缀；安装后显示的名称和标题不一致（3.6.4）。
   - **合规**：缺适龄标识或隐私政策入口、首次收集信息前没有弹窗（8.1）、广告位置或频率违规（1.3.x）。按 [build.md](build.md) 第 5 节和 [capabilities.md](capabilities.md) 的广告一节改。
   - **包体**：没接 TapTap 登录（5.2.4），包体超过 20 MB（5.2.2）。
3. 只改资料、不动代码时：直接改商店资料，再提交。
4. 要改代码时：重新构建，上传更高版本号的包体，通过准入测试，在商店资料里重新选这个包体，再提交。
5. 不要原样重复提交。看不懂驳回原因时，请用户在后台「工单」里咨询。

## 5. 上线之后

- 审核通过后，到了设定的上线时间，游戏以「开放试玩」对玩家可见。审核通过不等于已经上线。
- 发新版本的顺序 [官方](https://developer.taptap.cn/minigameapidoc/quick-start/guide/creation-improvement/)：
  1. 上传更高版本号的包体，通过准入测试；
  2. 在「商店 → 版本管理」新建版本（「+」，会复制上一版的全部资料）；
  3. 在「游戏下载和获取」里选新包体；
  4. 提交，一般 1 天内出结果。
- 只改商店素材或文案，不用换包体，改完提交即可 [官方](https://developer.taptap.cn/agents.md)。
- 想看数据和评价：后台的「数据分析」，或者用 CLI 的 `dashboard-stats`、`player-feedback` 相关命令（见 automation.md）。
