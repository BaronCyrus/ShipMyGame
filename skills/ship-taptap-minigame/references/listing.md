# 商店资料：字段、文案、素材

本文对应 SKILL.md 的 P6。字段和限制以 2026-11-02 晚在真实后台读到的页面原文为准 `[实测]`。官方文档写得更严的地方单独列出来，按更严的准备。

## 1. 页面和保存

- **入口**：商店 → 版本管理 → 未发布版本「V-<日期>」，网址 slug 是 `update-app-v2?panel=basic_info&version=V-<日期>` `[实测]`。
- **页签**：基础信息 / 游戏下载和获取 / 游戏资料 / 隐私说明 / 其他。页面底部是「发布设置」（定时上线 / 立即上线）和「下一步」`[实测]`。
- **保存**：表单自动保存，右下角会显示「HH:MM:SS 已保存」。离开页面时会弹「Leave site?」，要去别的页面就另开标签页 `[实测]`。
- **顶部提示**：「游戏资质待补充」，原文四条 `[实测]`：
  - 正式上线开放下载或开放内购，必须提供官方游戏出版物号（ISBN）；
  - 提供 APK 测试、下载，必须完善未成年人防沉迷系统，并提供接入视频证明；
  - 联网游戏提供包体测试、下载，请提供 App 的 ICP 核准信息；
  - 联网游戏提供小游戏方式游玩，必须在 TapTap 平台完成小游戏的 ICP 核准流程。

  只发小游戏、没有内购时，要处理的只有最后一条，也就是前置备案，见 [filing.md](filing.md)。
- **必填项**（带 *）：基础信息里的厂商类型、游戏平台、版本名称；Android、iOS 两个游戏状态；游戏名、简介、游戏图标、游戏截图、游戏实机录屏、宣传图（16:9）、首页推荐素材；隐私政策链接；游戏内是否提供 AI 合成服务。上传竖版录屏后，还要加上宣传图（1:1）`[实测]`。

| 字段 | 选项或内容 | 推荐 |

| APK 包名 | 选填 | 只发小游戏就留空 |
| 版本名称 | 自动填成 `V-<日期>` | 不用改 |
| 适龄分级 | 8 周岁+ / 12 周岁+ / 16 周岁+ | 和游戏内的适龄标识、适龄提示一致。审核通过后显示在详情页游戏名下方 [官方](https://developer.taptap.cn/minigameapidoc/tap-operation/operation-standards/age-rating/) |

## 3. 游戏下载和获取

| 项 | 选项 | 推荐 |
|---|---|---|

## 4. 游戏资料（Android、iOS 两个页签）

iOS 页签的游戏名和简介可以单独填；图标、截图、宣传图不传时跟随 Android `[实测]`。

| 字段 | 页面要求（2026-11-02 原文要点）`[实测]` | 推荐做法 |
|---|---|---|
| 游戏名 | 不超过 50 字符；勿加无关词缀与特殊符号 | 和游戏内名称（`productName`）一致（审核规范 3.6.4）；不用「最」「第一」「极速版」 |
| 简介 | 仅用于介绍游戏本身；勿填联系方式、外链、兑换码 | 300～500 字。用【玩法】【特色】这样的小标题加「·」列表分段，换行会保留 |
| 开发者的话 | 不超过 5000 字；勿填联系方式、外链、兑换码；不得与简介高度重合 | 100～200 字，写设计初衷，不要复述简介 |
| 游戏图标 | 不得用白底、黑底、透明底；不要自己切圆角，传方图；JPG/PNG，不小于 512×512 | 512×512 PNG，主图形撑满画布；不加 NEW、HOT、红点角标（审核规范 3.2.9） |
| 游戏截图 | 至少 3 张，JPG/PNG，单张不超过 4 MB。开放下载或试玩时，必须有核心玩法的实机截图：实机画面面积超过 50%，概念图或广告图最多 2 张且排在实机截图之后，不能只放商业内容。横图宽高比 8:3～8:5、不低于 1280×720；竖图 3:8～5:8、不低于 720×1280；所有图的比例要和第一张一致 | 竖屏游戏放 5～6 张竖图，可以一次多选上传。不要手机状态栏、平台胶囊按钮、水印（审核规范 3.3.2、3.3.7） |
| 游戏实机录屏 | 开放下载或试玩时必填。前 5 秒内展示核心玩法，且持续 10 秒以上；不要人声配音、字幕、画中画、设备界面。时长 15 秒～30 分钟，建议 2 分钟内；.mp4/.mov，H.264/HEVC，不超过 5 GB；短边不低于 540，宽高比 21:9～9:21 | 20～60 秒，1080×1920 H.264 带静音音轨，第 2 秒就开始操作。实测 20.5 秒的视频约 700 KB，上传后 3 分钟内转码完成 |
| 宣传片 | 选填；只支持横屏 16:9，不低于 1280×720，不短于 15 秒，不得和实机视频高度雷同 | 一般不传 |
| 宣传图（16:9） | 图中要有游戏标题，标题以外不能有宣传文字；不能出现游戏图标；不能直接用截图或简单拼贴；要贴近真实美术。JPG/PNG，不超过 4 MB，不低于 1920×1080 | 1920×1080 JPG，200 KB 左右。做法见第 8 节 |
| 宣传图（1:1） | 上传竖版实机录屏后出现，而且必填（用作竖版录屏的封面）。规则同上，不低于 1440×1440，核心视觉和 16:9 那张一致 | 1440×1440 JPG |
| 首页推荐语 | 不超过 25 字符；勿用极限词 | 客观写一个亮点，不写「最」「第一」「无广告」「不氪金」（通用审核细则 2.9） |
| 首页推荐素材 | 三选一：宣传图 (16:9) 不使用任何视频素材 / 游戏实机录屏视频 / 宣传片。素材没传好之前是灰的 | 选「游戏实机录屏视频」`[实测]` |

**官方文档更严的地方**：小游戏《宣发物料指引》写的是宣传图不超过 2 MB、截图单张不超过 2 MB、录屏不超过 500 MB 的 mp4，和后台页面的数字不一样 [官方](https://developer.taptap.cn/minigameapidoc/quick-start/guide/game-publish/material/)。**按 2 MB 和 500 MB 准备**，两边都满足。通用版《游戏物料要求》（页面显示「版本：v4」）的尺寸和后台一致 [官方](https://developer.taptap.cn/docs/store/release/publish/material/)。

## 7. 隐私政策网页

审核要求隐私政策链接有效、内容和游戏内一致 [官方](https://developer.taptap.cn/docs/store/release/policy/policy-guide/)。

1. 用游戏内的同一份文案生成网页，保证逐字一致：
   ```bash
   python3 <skill>/scripts/make_privacy_page.py <工程>/Assets/Resources/ShipCompliance/zh-Hans.txt \
     --out <工程>/publish/taptap/privacy/index.html
   ```
2. 托管到一个 https 公网地址，例如用户自己的 GitHub Pages、对象存储静态网站。推送或发布前征得用户同意 `[实测]`。
3. 从国内网络直接打开验证：返回 200、文字完整、没有乱码。然后把网址填进「隐私政策链接」。
4. 以后改了隐私政策：同时更新游戏内文案、网页和隐私保护指引，并提高 `policy_version`。

隐私政策正文要写清以下内容（`templates/compliance.zh-Hans.txt` 里已经按这个结构写好）：
- 处理了哪些信息、目的是什么、由谁处理（TapTap 登录、成就、排行榜的数据由 TapTap 处理）；
- 本地存档；
- 不收集哪些信息；
- 第三方 SDK；
- 怎么删除；
- 未成年人保护；
- 用户权利；
- 更新方式；
- 联系方式。

依据：行为规范第三章 [官方](https://developer.taptap.cn/minigameapidoc/tap-operation/operation-standards/behavior-standards/)。

## 8. 素材怎么做

通用做法见 [store-assets.md](../../ship-my-game/references/store-assets.md)，下面只写 TapTap 特有的要点 `[实测]`。

**截图**：
- 用安卓模拟器（1080×1920）跑游戏的「截图构建」逐张截取，或者请用户在真机上截。
- 截图里不能有手机状态栏，也不能有任何平台的胶囊按钮、菜单等界面元素：有的就裁掉或用背景色覆盖。
- 实测把别的渠道的截图拿来复用时，必须抹掉那个平台的界面元素。用背景色覆盖会盖到内容时，直接裁掉顶部。

**宣传图（16:9 和 1:1）**：用 Python + Pillow 合成，脚本放在 `publish/taptap/`，改文案后一条命令重出。
- 渐变底色，加上游戏里的玩法元素和美术。
- 游戏名或中文 logo 是**画面上唯一的文字**。
- 画面主体不要用和图标相同的形象，避免被判「使用 ICON 素材」（审核规范 3.4.4）。
- 不要直接贴截图，也不要多图拼接（3.4.2、3.4.3）。不要画实物手机（3.4.7）。
- 16:9 和 1:1 两张的核心视觉要一致。

**实机录屏**：
1. 在 1080×1920 的安卓模拟器上，用调试启动参数直接打开一个关卡。
2. 用 `adb shell screenrecord --bit-rate 8000000` 录制，同时用 `adb shell input tap/swipe` 操作，第 2 秒就开始玩。
3. 转码：

```bash
ffmpeg -i demo.mp4 -f lavfi -i anullsrc=channel_layout=stereo:sample_rate=44100 \
  -vf "fps=30,scale=1080:1920:flags=lanczos,format=yuv420p" -c:v libx264 -profile:v high -preset slow -crf 18 \
  -c:a aac -shortest -movflags +faststart publish/taptap/video/gameplay.mp4
```

- 模拟器录的是安卓原生构建的画面，不是小游戏容器里的画面。上线前最好用真机上的 TapTap 版重录一次，或者至少确认画面一致（例如新加的适龄标识、隐私按钮也要出现）。这一点是推断。
- 竖版录屏会多出「宣传图（1:1）」这个必填项，要提前做好。

**文件放置**：所有素材和生成脚本都放在 `<工程>/publish/taptap/`，文件名用 ASCII，按[上传方法](../../ship-my-game/references/uploads.md)传：10 MB 以内用浏览器工具，图片可以一次多选。

## 9. 和商店资料有关的审核条文

下表来自《小游戏审核规范》[官方](https://developer.taptap.cn/minigameapidoc/tap-operation/operation-standards/review-standards/)；通用的《TapTap 游戏审核规范细则》（页面显示「版本：v4」）有对应条文 [官方](https://developer.taptap.cn/docs/store/release/publish/agree/)。

| 条文 | 要求 |
|---|---|
| 3.1.4 / 3.1.7 / 3.1.8 | 不得含商店评分；不得引导到其他网站；不得含微信号、QQ 号、二维码 |
| 3.1.9 / 3.1.11 | 图片清晰、不拉伸；需要简体中文 |
| 3.2.6 / 3.2.9 | 图标不切圆角；不加 NEW、HOT、红点角标 |
| 3.3.2 / 3.3.7 | 截图不得有手机界面，不得重复同一张；不得加水印、时间戳 |
| 3.4.1～3.4.4 / 3.4.7 | 宣传图要有游戏名且只有游戏名；不直接用截图；不拼接；不出现图标；不出现实物手机 |
| 3.5.4 / 3.5.7 / 3.5.8 | 简介和开发者的话不得引导好评；不含兑换码、交流群、外链（Steam 和 TapTap 详情页除外）；两者不得高度相似 |
| 3.6.4 / 3.6.7 / 3.6.8 | 安装后显示的名称要和标题一致；标题不用「最高级」「最好玩」这类词；有软著、版号的，标题要和它们完全一致 |
| 3.7.1 / 3.7.2 | 视频不得有其他平台或剪辑软件的水印，不得有手机界面 |
