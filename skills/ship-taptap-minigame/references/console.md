# 后台页面怎么填（小游戏管理）

本文对应 SKILL.md 的 P3、P4，讲「商店 → 游戏包管理 → 小游戏管理」下的各个页面。商店资料见 [listing.md](listing.md)，前置备案见 [filing.md](filing.md)，页面网址的拼法见 [onboarding.md](onboarding.md)。下文页面原文均为 2026-11-02 在真实后台读到的 `[实测]`。

## 1. 基础配置

在「小游戏管理 → 基础配置」，网址 slug 是 `tap-mini-app-config`。页面分三块 `[实测]`：

- **服务内容声明**
  - 提示「当前版本未填写隐私收集情况，请前往小游戏资料 更新版本」：这里说的是商店资料「隐私说明」页签里的「小游戏隐私设置」，见 listing.md。
  - 「隐私保护及权限设置：待提交」，说明文字是「您需要完成相应设置，才能够正常在游戏内调用 API，请求系统信息」。右边有「当前版本」「协议配置」两个按钮，怎么填见第 5 节。
- **域名配置**：request、socket、uploadFile、downloadFile、udp、tcp 六类合法域名。没有服务器的单机游戏不用填。要填的话有这些要求 [官方](https://developer.taptap.cn/minigameapidoc/dev/tutorial/basic/network/)：
  - 只能是 HTTPS 域名；
  - 不能用 IP，也不能带端口；
  - 域名必须完成 ICP 核准。
- **版本设置**：小游戏最低支持基础库版本、小游戏最低可用版本。没有特殊要求就不用设。

## 2. 开放能力

在「小游戏管理 → 开放能力」，slug 是 `tap-mini-app-capability` `[实测]`：

- 「小游戏基本信息」一块写着：
  - `MiniApp ID：… 复制`：复制下来写进 `publish/taptap/build.json`。
  - `Secret：****** 查看`：不要点，不要外传。
  - `适用地区：中国大陆`。
- 页面上还列着各项开放能力：TapTap 登录、云存档、创建桌面图标、分享与好友、成就、排行榜等。接入方法见 [capabilities.md](capabilities.md)。

## 3. 包体管理

在「小游戏管理 → 包体管理」，slug 是 `tap-mini-app-package` `[实测]`。

**页面上的说明**：
- 包体类型只有「TAP 包体」一种，说明是「小游戏引擎打包出的指定 zip 文件，支持 WASM 分包」。
- 页面警告「首次上传后包体类型即锁定，发布正式版本后不可更换包体类型」。
- 四条要求：
  1. 包体必须是 TapTap 打包工具打出的 zip；
  2. 包体大小限制为 20MB 以下；
  3. 上传后会自动读取包体引用的小游戏库版本；
  4. 请确保上传包体内已正确接入 TapTap 登录。
- 「通过自测的包体您可用以：提交小游戏备案；填入游戏资料，正式上线/更新对应的游戏版本」。

**顶部黄条**（可能出现）：
- 「隐私保护及权限设置未填写」：隐私保护指引提交后、审核期间，这条仍然显示「未填写」，不用理会。
- 「小游戏上架资质待补充」：列出防沉迷、版号、备案、ICP 核准等缺口。没有版号的游戏，防沉迷由平台自动生效；备案见 filing.md。

**按钮**：「上传包体」「设置自测用户」。

**表格**：开发版本 / 审核版本 / 线上版本配置三张表。
- 列：小游戏版本对照、版本号、上传人、包体准入测试、是否分包、上传时间、最低支持库版本、操作。
- 开发版本只显示最近 5 个。
- 开发版本一行的操作是「自测 | 编辑 | 提审」，测试结束后还会多出「查看报告」。

### 3.1 上传抽屉「上传新包体」

上传抽屉分两步。也可以不用网页，改用 CLI 上传，见 [automation.md](automation.md) `[实测]`。

**第 1 步「上传包体与版本设置」**：
1. 文件框是 `input[type=file][accept=".zip"]`，选 `game.zip`。框旁边的提示写着「请确保包体文件大小 < 300MB」。
2. 怎么把文件放进去：
   - 不超过 10 MB：用浏览器工具的上传功能。
   - 超过 10 MB：用[本机中转](../../ship-my-game/references/uploads.md)，在页面里执行 `__pub.put('input[type=file][accept=".zip"]', "http://127.0.0.1:8765/game.zip")`。实测 14 MB 的包约 8～10 秒传完。
3. 等页面显示「game.zip (… MB) 上传时间 … 重新上传 | 删除」。
4. 「该包体对应版本号 *」填三个数字（V . .），要和 `build.json` 的 `version` 一致。「该包体最低支持小游戏库版本」是自动识别的，不用填。
5. 点「下一步」。

**第 2 步「分包管理与包体自测」**：
1. 「是否开启WASM分包？」：没有分包需求就选「暂不开启」。实测上传的包，这里显示「当前小游戏不支持分包」。
2. 先在对话里告诉用户版本号和改了什么，用户同意后再点右下角「提交」。点「提交」后，这个版本进入「开发版本」表，并自动开始包体准入测试。
3. **实测这个「提交」被 agent 的权限系统拦下过**，原因是 `Unrequested Commit in a Connected App`。被拦就把抽屉停在第 2 步，标签页不要关，告诉用户去哪个标签页点右下角的「提交」。

抽屉里的坑 `[实测]`：
- **在抽屉里换包会卡死**：点「上一步」回到第 1 步再换一个 zip，云存储上传成功了，但后台的 `complete-upload-task` 返回 500，抽屉一直停在「正在上传包体，请勿离开当前页面」。处理：点「取消上传」→ 关掉抽屉 → 重新点「上传包体」。
- **抽屉开着时页面跳走，没提交的上传会作废**。需要去别的页面时，另开一个标签页。

### 3.2 扫码自测

- 点开发版本一行的「自测」，弹出「扫码自测」。把二维码截图发给用户，请他用**最新版 TapTap** 扫码 `[实测]`。
- 弹窗里的说明：扫码后会自动拉起小游戏，出现异常就重新扫码；扫过码的设备再启动这个游戏时，会一直显示「内部测试」提示 `[实测]`。
- 用 CLI 也能拿到自测二维码 PNG，见 automation.md。
- TapTap App 要求安卓 2.83.0 及以上、iOS 4.55.0 及以上。开发者账号默认有测试权限；其他账号在「设置自测用户」里加，要填对方的 TapTap 用户 ID [官方](https://developer.taptap.cn/minigameapidoc/dev/dev-support/debugging/)。
- 让用户在真机上逐项确认：能进游戏、有声音、中文正常、登录弹窗和隐私弹窗正常、退出重进后存档还在、刘海和右上角胶囊按钮没挡住界面。

### 3.3 包体准入测试报告

- **触发**：开发版本「提交」后自动开始，表格里显示「测试中」。安卓 5 台加 iOS 1 台，10 分钟内出结果 `[实测]`。
- **设备**：每次测试的设备不固定。实测两次用的设备品牌包括 OPPO、华为、小米、vivo、一加，第三次换成荣耀、OPPO、红米、vivo，所以不能只针对某几款机型调 `[实测]`。
- **通过线**：报告写「Android（通过标准·80%）」，也就是 5 台里至少 4 台通过。iOS 那一行的机型、品牌都是「-」，显示的「已通过」只是占位，不代表在 iOS 上跑通过 `[实测]`。
- **报告页**：点「查看报告」，网址是 `tap-mini-app-package?taskID=<任务ID>`。内容包括 `[实测]`：
  - 整体结果；
  - 运行测试：Android、iOS 各自的通过率和设备数；
  - 性能测试：启动耗时、内存峰值、内存均值、FPS、卡顿率。会跑 10 分钟；运行测试失败时这里显示「-」；
  - 优化建议；
  - 设备表：品牌、机型、系统版本、分辨率、测试结果、异常类型、「下载日志」。实测见过的异常类型有「黑白屏」和「小游戏加载失败」。
- **下载日志**：会触发浏览器下载，先告诉用户文件名、来源（阿里云 OSS）和大小（每份 0.7～1.8 MB），用户同意后再点 `[实测]`。日志包里有：
  - 每 2 秒一张的截图和 `test_over.jpg`；
  - `js_log.log`（有时没有）；
  - `logcat.txt`、`log.log`；
  - `autotest.json`（设备信息）；
  - `list_traversal_*.log`（自动遍历记录）。

  怎么看这些日志，见 [troubleshooting.md](troubleshooting.md)。
- **没通过**：「消息中心」会收到「Tap小游戏版本未通过自动化测试」的通知 `[实测]`。修好后换一个更高的版本号重新上传。

## 4. 小游戏资质

在「小游戏管理 → 小游戏资质」，slug 是 `tap-mini-app-qualification`。页面分三块 `[实测]`：

- **未成年人防沉迷**：「游戏未上传版号 — 暂不需要办理防沉迷内容，线上游戏将会自动生效防沉迷系统」，状态是「无版号游戏·自动生效中」。只以小游戏形式提供时不用做任何事 [官方](https://developer.taptap.cn/minigameapidoc/quick-start/guide/creation-improvement/)。
- **小游戏前置备案**：状态「待提交」，按钮「提交核准信息」。见 filing.md。
- **游戏资质**：跟着游戏走，不分 APK 和小游戏，包括版号（ISBN）、未成年人防沉迷、安全评估报告、软件著作登记、相关授权书，入口是「前往补充游戏资质」。没有内购的小游戏不需要版号 [官方](https://developer.taptap.cn/minigameapidoc/quick-start/guide/creation-improvement/)。

## 5. 隐私保护及权限设置（《小游戏隐私保护指引》）

**入口**：基础配置 →「隐私保护及权限设置」→「协议配置」，slug 是 `tap-mini-app-config/privacy-policy`。页面开头写着「根据所提交的代码版本，识别到小程序调用了收集用户个人信息的接口，请按照小程序实际运行情况，认真填写以下内容」，下面是指引模板，游戏名和厂商名会自动带入 `[实测]`。

逐项填写 `[实测]`：

| 部分 | 操作 | 怎么选 |
|---|---|---|
| 1. 开发者处理的信息 | 「增加信息类型」弹出 14 类信息和对应接口。例如：昵称头像对应 `scope.userInfo`、`getUserInfo`、`createUserInfoButton`；位置信息对应 `getFuzzyLocation`；好友关系对应 `scope.friendInteraction`（好友排行榜）；还有 Tap 好友列表、麦克风、摄像头、蓝牙、相册、剪切板、各类传感器 | **只勾游戏真正调用的接口**。只用 TapTap 登录、公开排行榜和成就时，实测可以一项不勾；用好友排行榜必须勾「好友关系」，否则会报 1025 [官方](https://developer.taptap.cn/minigameapidoc/dev/api/open-api/leaderboard/tap.getLeaderboardManager/) |
| 2. 第三方插件 / SDK 信息 | 「增加第三方 SDK 信息」 | 只接了 TapTap SDK 时不加；接了广告 SDK 等第三方组件要如实写 |
| 3. 你的权益 | 「增加联系方式」：在固定电话、手机号、邮箱里选类型，再填内容 | 用公开的联系邮箱，和隐私政策里写的一致 |
| 4. 开发者对信息的存储 | 二选一：「固定存储期限 [ ] 年/月」，或「开发者承诺…保存期限应当为实现处理目的所必要的最短时间」 | 没有服务器就选第二个 |
| 5～7 | 固定文字 | 不用填 |

提交：
1. 勾选「本小程序已对用户的信息处理进行了逐一、如实的说明，并保证如有变更会及时更新指引」。
2. 点「预览」，再点「确定并生成协议」。
3. 提交后状态是「审核中」，旁边有「当前版本」「撤销审核」两个按钮。

实测：用户明确说「你来填」之后由 agent 代填并提交，没有被拦，全程约 3 分钟 `[实测]`。

这里的选择要和商店资料里的「小游戏隐私设置」、游戏内的隐私政策三者一致：都写「不处理」，或者都如实列出。

## 7. 在这个后台里操作浏览器的经验

以下都在用户自己的 Chrome 里实测过 `[实测]`：

- 后台是 antd 组件，文件框是隐藏的。用查找工具找带「(file)」的元素再上传，或者用 `__pub.list()` 列出来。
- 下拉框、单选按钮：按元素引用点击有时会点到别的按钮（成就表单里按引用点「提交」，结果点到了「取消」）。先用 JS 读出按钮的坐标，再按坐标点。
- 数字框填完要按 Tab 或点一下空白处，才会触发校验。
- 上传图标后页面会重绘、丢失焦点，等 2 秒再填文字。
- 有的页面读文字工具返回空，改在页面里执行 `document.querySelector('main').innerText`。
- 输出里带查询串的网址可能被工具打码。读网址前先去掉 `?` 后面的部分。
- 页面跳转时弹出「Leave site?」拦截：商店资料草稿是自动保存的，需要去别的页面时另开标签页。
- 不要关用户正在用的标签页，关旧标签可能把整个标签组一起关掉。
- 等准入测试时设一个约 7 分钟的计时，到点再回来看，不要一直刷新页面。
