# 小游戏前置备案

本文对应 SKILL.md 的 P5。前置备案是 TapTap 给普通小游戏提供的一站式备案，把原来的小游戏备案和 ICP 核准合在了一起。小游戏正式上架前必须完成 [官方](https://developer.taptap.cn/minigameapidoc/quick-start/guide/pre-filing/)。没有内购的小游戏不需要版号，但要做这个备案 [官方](https://developer.taptap.cn/minigameapidoc/quick-start/guide/creation-improvement/)。

**时机**：备案要选一个已上传的包体。所以第一个开发版本一上传，就马上开始填。官方流程图允许先传一个 DEMO 包（可以暂时不接平台能力）来申报 [官方](https://developer.taptap.cn/minigameapidoc/quick-start/guide/minigames-intro/)。全程约 20 个工作日，是整个发布流程里最长的一段。

## 1. 入口和三个步骤

**入口**：商店 → 游戏包管理 → 小游戏管理 → 小游戏资质 →「小游戏前置备案」卡片 →「提交核准信息」`[实测]`。卡片上的说明是「根据工信部管理规定……小游戏需要依托于平台进行重新核准」，状态显示「待提交」。

**三个步骤** [官方](https://developer.taptap.cn/minigameapidoc/quick-start/guide/pre-filing/)：① 填写核准资料 → ② 电子化核验 → ③ 提交审核。

## 2. 第一步：填写核准资料

表单右侧有锚点导航：开发者认证 / 小游戏包体 / 软件著作权人 / 游戏内容介绍说明 / 小游戏负责人基本情况 / 身份信息核验 / 补充材料 `[实测]`。

| 模块 | 字段与要求 | 谁做 | 依据 |
|---|---|---|---|
| 开发者认证 | 只显示认证状态 | — | `[实测]` |
| 小游戏包体 | 选一个已上传的开发版本。表格列：已选择包体、更新时间、版本号、最低支持库版本；可以「重新选择」。实测页面允许选一个准入测试没通过的版本；这样会不会影响备案结果，未确认 | 你 | `[实测]` |
| 软件著作权人 | 只有一个「著作权人名称 *」文本框，**没有上传证书的地方**。实测没有软著，用户填了本人姓名；会不会因此被退回，未确认 | 用户提供名称，你填 | `[实测]` |
| 游戏内容介绍说明 * | 上传 DOC/DOCX，单个不超过 50 MB。说明文字是「可以简要描述游戏每个环节、场景，图文并茂」，旁边有「参考范例」。已经有版号的，上传版号后就不用交这一项 | **你**：按第 4 节生成并上传 | `[实测]` |
| 游戏简介 * | 「请用一句话简单描述你的游戏，建议30字以内」 | **你** | `[实测]` |
| 小游戏负责人基本情况 * | 姓名、有效证件类型（中国大陆身份证）、证件号码、证件有效起止日期（可以勾「长期有效」）、手机号码、电子邮箱、应急联系电话。**个人主体时，负责人必须是认证主体本人** | **用户本人** | `[实测]` [官方](https://developer.taptap.cn/minigameapidoc/quick-start/guide/pre-filing/) |
| 身份信息核验 | 上传负责人身份证件 *（JPG/PNG，正反面，单个不超过 10 MB），以及相关主体证明材料 | **用户本人** | `[实测]` |
| 补充材料 | 「服务核准承诺书」必填：JPG/PNG 扫描件，单个不超过 10 MB，有「下载模板」。「不涉及前置审批承诺书」选填，也有模板。「小游戏负责人授权书」由系统根据主体情况判断是否需要，企业才会用到 | 承诺书：你做待签版，**用户签字** | `[实测]` |

全部填完后，点右上角「下一步」进入电子化核验 `[实测：按钮存在]`。

## 3. 服务核准承诺书（用户手签）

模板里有「单位」和「个人」两份，个人主体用「互联网信息服务核准承诺书（个人）」。正文是六条固定承诺，落款是「签名：」「身份证号码：」「年 月 日」`[实测]`。

1. **你**：把个人版正文一字不改地排成 A4 页，生成 docx 和 PDF，放进 `publish/private/taptap/`。
2. **用户本人**：打印，手写签名、身份证号和日期。
3. **用户本人**：拍照或扫描成 JPG/PNG，单个不超过 10 MB。照片要四角完整、字迹清晰。
4. 上传到「补充材料 → 服务核准承诺书」：用户自己传，或者把文件交给你代传。

签名和身份证号**不能由你代写**。文件里有身份信息，不进 git，用完提醒用户自己留存。

## 4. 《游戏内容介绍说明》（你来写）

先读官方参考样式，再照着结构写。可以从 `templates/game-content-intro.md` 起草：它按官方目录列好了章节、必要项和次要项、没有该内容时的标准写法，不含任何真实材料 `[实测：结构取自官方参考样式]`。

| 章节 | 性质 | 写什么 |
|---|---|---|
| 一、游戏总体介绍 | 必要 | 依次写：什么类型的游戏、玩家扮演谁、在游戏里做什么、靠什么玩法、最终达到什么目标、主体思想 |
| 二、游戏背景 | 次要 | 没有就写「本游戏无任何剧情背景」 |
| 三、主要角色（扮演角色） | 次要 | 文字加图片；没有就写「本游戏无任何角色出现」 |
| 四、场景介绍 | 次要 | 场景、地图各配 3～5 张图和说明；只有单一背景就写「本游戏仅存在单一（或纯色）背景，不包含任何违规场景」 |
| 五、主要情节 | 次要 | 没有就写「本游戏无任何剧情/关卡/情节」 |
| 六、玩法 | 必要 | 图文说明核心玩法和其他玩法 |
| 七、功能（系统）介绍 | 必要 | 每个功能的入口、怎么用、有什么效果，配图 |
| 八、道具、装备说明 | 次要 | 没有可以不写 |
| 九、技能说明 | 次要 | 没有可以不写 |

实测写法（休闲单机游戏）`[实测]`：
- 第一到第七节照官方目录写，第八节改成「其他说明」：单机、没有联网、聊天和用户生成内容，没有付费，没有广告，进度只存在本地，没有服务器。
- 配 11 张实机截图，每节 2～3 张并排，带图注。
- 「功能（系统）介绍」一节逐条写清每个功能的入口和效果：提示、设置、每日挑战、解锁规则、主题、统计、成就和排行榜、隐私保护与适龄提示。
- **动笔前先在游戏里逐条核对真实规则**，文档写的必须和游戏实际一致。
- 用 python-docx 生成 docx，约 1.5 MB。也可以先写 Markdown，再用 `pandoc 游戏内容介绍说明.md -o 游戏内容介绍说明.docx` 转换（pandoc 这条路未实测）。

截图来源：用 P6 做商店截图时的那套方法（模拟器截图构建或真机截图），画面里不要出现真实昵称和头像。

## 5. 第二步：电子化核验（用户本人）

在「电子化核验」页点「生成核验码」，由负责人用微信或支付宝扫码，约 10 分钟。在页面上看「核验状态」，变成通过后才能进入下一步 [官方](https://developer.taptap.cn/minigameapidoc/quick-start/guide/pre-filing/)。

## 6. 第三步：提交审核

1. 先把填好的内容列给用户：选了哪个包体、游戏简介、上传了哪些文件。
2. 用户确认后，点右上角「提交核准信息」[官方](https://developer.taptap.cn/minigameapidoc/quick-start/guide/pre-filing/)。被权限系统拦下时，停在这个按钮上，请用户点。
3. 页面进入「审核中」状态。

## 7. 等待和短信核验

依据 [官方](https://developer.taptap.cn/minigameapidoc/quick-start/guide/pre-filing/)：
- 全程预计 20 个工作日内完成；其中初审约 12～16 个工作日。
- 初审通过后，工信部会给负责人发短信。**24 小时内**没按提示完成认证，申请会被自动退回，需要重新提交。所以要提前告诉用户留意短信。
- 审核期间保持负责人手机畅通。
- 通过后，在「小游戏资质」页点「查看核准信息」，能看到服务核准号、主办单位名称和服务名称。

进度档案的「等待中」要写：提交日期、预计完成日期（提交日加 20 个工作日）、提醒用户留意工信部短信、在「小游戏资质」页看结果。
