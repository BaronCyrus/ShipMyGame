# 名称、素材与文案

微信小游戏没有单独的「商店页」。信息来自四处：
- 「账号设置 → 基本设置」里的名称、头像、介绍；
- 小游戏备案里的截图和文字（审核用，用户看不到）；
- 提审时的版本说明和宣传图；
- 「运营素材管理」里的游戏简介、封面、推广图、推广文案和推广视频：决定搜索结果、发现页、游戏中心里怎么显示，见下面「运营素材」。

分享卡片的图片在[能力接入](capabilities.md#分享)里。

## 名称、简称、头像、介绍

**修改次数限制**（已在后台核对）
- 名称：每年 2 次，页面写认证后重置。
- 头像：每年 5 次。
- 介绍：每月 5 次。

**名称规则**
- 用纯中文：
  - 名称里有英文或「软件」二字，或者涉及品牌、公众人物时，资质审核要交软件著作权登记证书 `[官方]`（[资质审核-IAA](https://developers.weixin.qq.com/minigame/introduction/guide/zzsh-iaa.html)）。
  - 实测用纯中文名，没有被要求交软著 `[实测]`。
- 游戏里显示的名称必须和后台名称一致。备案截图要求能看到当前小游戏名，所以主页标题就用这个名字 `[实测]`。
- 和已获批的游戏重名时，小游戏备案会被驳回。名字要和玩法相关，例如不能把与三国无关的消除游戏叫成三国类名字 `[官方]`（[小游戏备案 Q4](https://developers.weixin.qq.com/minigame/introduction/guide/nrjs.html)）。
- 名称的通用规范见 [名称设置规范](https://kf.qq.com/faq/170109umMvm6170109MZNnYV.html)（腾讯客服，官方指南链接到这里）。
- 设置后的生效时间 `[官方]`（[名称](https://developers.weixin.qq.com/minigame/introduction/guide/name.html)）：
  - 正常情况立即生效；
  - 命中保护词要补材料，需要 1～3 个工作日；
  - 名称被占用可以发起侵权投诉，处理需要 7 个工作日，成功后还有 7 个自然日的保护期。
- **提交资质和小游戏备案之前把名字定死**：之后到小程序备案完成前都不能改 `[实测]`。

**头像**
- 用游戏图标。
- 后台对尺寸和格式的要求，以上传框的提示为准（本仓库**未记录**）。

**介绍**
- 一两句话写清楚玩法和特色。
- 不写联系方式，不写诱导性的词。

## 备案截图

**规则**（备案表单原文要点，`[实测]`）
- 格式 JPG、JPEG 或 PNG，大小 60KB～5MB。
- 必须是在微信里运行的小游戏截图，截图里要看得到当前小游戏的名字。
- 场景、玩法各至少 3 张；每个系统至少 1 张。
- 同一批截图的尺寸和版本要一致 `[官方]`（[小游戏备案](https://developers.weixin.qq.com/minigame/introduction/guide/nrjs.html)）。

**截图只能由用户在手机上截** `[实测]`
- Mac 微信的路线走不通：推送后约 1 分钟窗口就关闭，并要求在手机上确认登录；截屏里主窗口也是空白。
- 不要用真机调试模式截图：画面右下角有 vConsole 按钮。

**你先做好这些准备**
1. 出一个专用于截图的预览版：
   - 主页标题显示中文游戏名；
   - 已关掉「优化建议」弹窗（`ShipWeChatBuild` 默认已关）；
   - 去掉英文 logo 和指向其他平台的按钮；
   - 截图画面里不要有真实昵称和头像。
2. 列出截图清单。每张写清：截什么画面、对应表单哪一栏。实测用过的清单结构如下（共 11 张）：

| 栏目 | 截图内容 |
|---|---|
| 场景（3 张） | 主页（带中文名标题）、关卡或内容选择页、游玩中的画面 |
| 玩法（3 张） | 刚开局、玩到一半、通关画面 |
| 每个系统（各 1～2 张） | 能看到该系统的界面，例如设置弹窗、带道具次数角标的游玩界面、日历或每日任务、解锁弹窗 |

3. 生成预览码（约 25 分钟有效），把清单发给用户。

**用户截完以后**
1. 用户用微信「文件传输助手」**勾选原图**发到电脑。
   - 网页版文件传输助手下载下来的文件名，是一长串带会话参数的字符串，不要外传。
2. 你按栏目重命名，用 ASCII 文件名，例如 `scene-1.jpg`、`system2-1.jpg`。
3. 检查格式和大小：每张都要在 60KB～5MB 之间。实测手机截图是 184～531KB。
4. 文件放进 `publish/wechat/filing/`，再按 [filing.md](filing.md#小游戏备案) 一栏一栏上传。

## 备案文字

用 `templates/filing-content.md` 写。要点：
- 场景：分「游戏主界面风格」「游玩界面风格」两段，最后补一句整体风格和不含哪些内容。
- 玩法：写规则、操作方式、目标、难度怎么递进、有没有失败惩罚、有没有体力限制。
- 系统：每个系统写入口在哪、怎么用、有什么限制。涉及广告的，写清「看激励视频能得到什么」，并反复说明没有货币、不能付费。
- 所有数字和规则都要先读代码核实，和游戏实际一致。

## 提审时的宣传图和版本说明

来源：[版本审核](https://developers.weixin.qq.com/minigame/introduction/guide/bbsh.html)，加上一次实测提审。

- 宣传图是选填项，分横版、竖版推广图；实测不传也通过了审核 `[实测]`。表单里只显示「暂未设置」，没有上传框，推测就是下面「运营素材」里的详细推广图。
- 版本更新说明：上限 300 字。首版写「首个上线版本：<一句话玩法>」，再分条列主要功能；之后每版写主要改动 `[实测]`。
- 表单的其他字段见 [review.md](review.md#提交审核表单)。

## 运营素材

「运营素材管理」决定小游戏在搜索结果、发现页、游戏中心、直播间卡片里怎么显示。提交后要审核，实测图文素材约 17 小时全部通过。实测是发布当晚填的 `[实测]`。

**入口和页面** `[实测]`
- 路径 `/wxamp/subApp/game/minigame/material_resource_management`，拼 token 的方法见 [console.md](console.md#读后台的技巧)。
- 正文在微前端（`<wujie-app>`）的 shadow root 里，读法和点法见 [console.md](console.md#读后台的技巧)。
- 顶部「点击查看 审核中版本(n)」打开审核列表：每项有类型、素材、提交时间、状态和「撤回」。
- 页面右侧会弹出「开发者助手」面板，点它右上角的收起按钮就不挡页面了。

**四栏和规则**（页面原文，2026-11-07 读到）

| 栏 | 项目 | 规则 | 修改次数 |
|---|---|---|---|
| 游戏介绍 | 游戏简介 | 单行，上限 20 字；官方简介撰写指南建议 16 字以内 | 每月 3 次 |
| 游戏介绍 | 通用素材封面 | JPG/JPEG，650×250，不超过 80KB | 每月 3 次 |
| 游戏介绍 | 详细介绍 | 就是「基本设置 → 介绍」，要在那里改 | 见上面「介绍」 |
| 素材推广 | 详细推广图（竖版） | 720×1280，三张，JPEG/JPG/PNG，每张不超过 200KB | 每月 3 次 |
| 素材推广 | 详细推广图（横版） | 1280×720，三张，其余同上 | 每月 3 次 |
| 素材推广 | 推广文案 | 上限 8 字，「请用简短的一句话展示游戏玩法亮点」，显示在直播间卡片 | 每月 3 次 |
| 素材推广 | 推广视频 | 一套是视频加封面。先选素材类型（「通用」或「实机画面」）和格式（横版或竖版），要求跟着变，见下面「做推广视频」。列表页建议至少传 3 套 | 每周 10 套 |
| 分享信息 | 分享图片 | 审核通过后拿到 `imageUrlId`，给分享接口用，见 [capabilities.md](capabilities.md#分享) | — |
| 内容素材 | 智能内容运营 | 开启后，平台在版本更新、进榜单、获得官方称号时自动生成帖子发到游戏圈 | — |

- 每月只能改 3 次，所以**先把样图和文案给用户看，用户同意再提交** `[实测]`。
- 编辑框旁有「AI智能生成」，实测没用。

**写简介和推广文案** `[官方]`（简介撰写指南整页是一张图：[minigame_desc_docs.jpg](https://res.wx.qq.com/wechatgame/product/webpack/userupload/20200106/minigame_desc_docs.jpg)）
- 两种写法：运营化，写新、热、版本、周年等关键信息，用情感化的语言；描述化，写基础玩法和题材。
- 错误示范有三类：
  - 描述空洞：换成任何游戏都成立的话，例如「沉迷在 XXXX，根本停不下来」；
  - 夸大宣传：例如「千万人都在玩」；
  - 涉嫌利诱：红包、分红、通关拿大奖。
- 实测提交的简介「按数字线索涂格子，揭晓隐藏像素画」（16 字）、推广文案「看数字涂出像素画」（8 字）都审核通过了 `[实测]`。

**做封面** `[官方]`（[封面图设计规范](https://game.weixin.qq.com/cgi-bin/minigame/static/minigame_setting/guide.html)，整页是图片）
- 主要图形居中或靠右（右侧 434×250），辅助图形放左侧（216×250）平衡画面。
- 不能出现游戏图标、logo、slogan 等标题文字。
- 图上的黑色蒙版由平台加，图里不要自带；用直角矩形，不要圆角。
- 实测做法 `[实测]`：用游戏自己的像素画，右边放一块正在揭晓图画的棋盘，左边放几幅小图；为了不算「出现图标」，棋盘里换了一幅和图标不同的画。审核通过。

**做推广图** `[官方]`（竖版设计指南也是一张图，上传页的「查看详细推广图（竖版）设计规范」链接）
- 通过局部放大、重新组合突出玩法，不建议直接用游戏截图。
- 画面要有游戏场景和体现玩法的关键元素，保持简洁，不许出现广告。
- 实测做法 `[实测]`：
  - 截图按目标语言（简体中文）的界面重拍。画面里有英文 logo、英文日期的不用。
  - 每张图：上方两行大字标题，中间是白色圆角框里的截图，再叠一块放大的局部（例如带数字线索的棋盘一角）或游戏里的小图。横版是左边标题、右边一到两个截图框。
  - 标题里的数字（图画包数、图画数、棋盘尺寸）先读游戏数据核实；「唯一解」「无需猜测」这类说法要有生成流程或代码作依据。
  - 体积限制：JPEG 质量从高往低试，第一个不超过限制的就用。实测 720×1280、1280×720 在 q≈89～95 时是 185～199KB，650×250 的封面 54KB。
  - 这样做的竖版、横版各 3 张都审核通过了。

**做推广视频**（上传页原文，2026-11-08 读到）

先选素材类型和视频格式，表单跟着变：

| | 通用 | 实机画面 |
|---|---|---|
| 视频 | 10～20 秒；横版不低于 1280×720，竖版不低于 720×1280，码率约 1M；MP4、H.264、AAC；小于 100M | 20～30 秒；横版正好 1920×1080，竖版正好 1080×1920；MP4；小于 50M；「需体现游戏核心玩法的真实画面」 |
| 封面 | JPEG/JPG/GIF/PNG；横版 16:9（建议 1280×720），竖版 9:16（建议 720×1280）；不超过 200KB；「请上传能体现游戏真实玩法的宣传图」 | 只收 JPG；横版 1920×1080，竖版 1080×1920；不超过 500KB；「需包含游戏品宣主视觉（包括角色任务、场景或玩法体现）、品牌 logo游戏名称」 |
| 推广文案 | 20 字以内，「可能会直接展示给用户」 | 没有这一栏 |

- 列表页写着「建议上传≥3套视频素材，有更高几率被推广」，每周能传 10 套。
- 开发者助手说实机画面「是专门服务于PC游戏场景的素材」。
- 没传实机画面时，首页顶部挂一条优化建议：「小助手发现游戏暂未上传『推广视频-实机画面』」。实测刚提交时这条还在，第二天早上就不显示了，当时视频还在审核中；三套都被驳回后它又显示出来，重新提交一小时后还在。

实机画面的「查看视频设计指南」是一张长图《[游戏预览视频制作指南](https://mmgame.qpic.cn/image/9d5a3daca032ed17baac602e0e0b911098468e26de9958ec835454b9a4dd9292/0)》（2025.11.05）`[官方]`：
- 横版游戏用 16:9，竖版游戏用 9:16；1080P、60fps；MP4、H.264；30 秒以内；小于 50M。
- 要体现游戏玩法和关键画面，包括人物角色、场景、玩法、声音、音乐。视频和封面严格同一比例。
- 避免这些：游戏 UI 干扰画面；开场、转场、加载；黑屏或白屏；任何弹窗；屏幕两侧黑边；营销文案或操作指引；大段无操作或等待；与游戏无关的片段；任何边框（封面也不加）。
- 「查看视频封面图设计指南」和开发者助手里的「设计指南」是微信开放社区的文章，要扫码登录才能看，本仓库没读到。

实测做法（竖屏游戏，实机画面 · 竖版）`[实测]`：
- 视频：
  - 1080×1920 的安卓模拟器正好是要求的尺寸。录法见 [store-assets.md](../../ship-my-game/references/store-assets.md#录屏实机演示视频)：
    - 截图构建直接打开空关卡，脚本按推理顺序拖动操作；
    - 停在过关弹窗出现之前，最后一帧多停 1.2 秒；
    - 成片 21～25 秒、60fps，每段约 1.8MB。
  - 模拟器录不到声音，后期合上了游戏自己的配乐和音效。
  - 做了 3 套，换了关卡和配色主题，免得三段一样。
  - 录的是同一个游戏的安卓构建，画面里没有微信的胶囊按钮，其他和微信里一样。
- 封面：**不要用录屏里的一帧**。
  - 第一次的封面是录屏里玩到一半的一帧，顶部标题栏换成游戏的中文 logo。三套都被驳回，驳回通知里只有封面一条原因，见下面「审核结果」。
  - 录屏帧上一定带着游戏的按钮（这次是底部的工具栏）。
  - 改成另画一张主视觉图：
    - 上面是游戏 logo（就是游戏名）；
    - 中间是这段视频里那幅画揭晓到一半的棋盘，一眼能看出玩法；
    - 下面摆四幅完成的小图，每套换一组；
    - 没有按钮、界面元素、说明文字和边框。
  - 棋盘和小图用游戏数据直接画，和图标、通用素材封面是同一种画法，不从截图里抠。1080×1920 JPG，约 310KB。
  - 视频没改，只换封面重新传了三套，结果待补。

**提交** `[实测]`
- 游戏简介、推广文案：点「编辑简介」，在输入框里打字，点「提交修改」。提示「修改成功」或「提交成功」后，这一项变成「审核中」。
- 通用素材封面：「上传图片」会对一个隐藏的文件框调用 `click()`。先截住它，再用本机中转把文件放进去，见 [uploads.md](../../ship-my-game/references/uploads.md#按钮用-click-打开文件框时)。出现缩略图和场景预览后点「提交」，提示「上传成功」。
- 详细推广图：「前往修改」会在新标签页打开上传页，路径 `/wxamp/subApp/game/old_minigame_setting/gameset`，竖版带 `type=vertical`，横版带 `type=horizontal`。
  - 这个页面直接往第 0 个文件框放文件就行。一张一张传，每张传完会列出文件名和缩略图（第一张还提示「上传成功」）。
  - 三张都出缩略图后点「提交」，页面跳到审核列表。
- 推广视频：列表页是「运营素材管理 → 推广视频」，「上传素材」会在新标签页打开上传页。
  - 这样打开的是 `pluginRedirect` 页，表单在跨域 iframe 里，页面脚本碰不到。改开 `/wxamp/subApp/game/old_minigame_setting/gameset?pageR=gameset&mod=video`（带 token），表单在 wujie 的 shadow root 里。
  - 选好素材类型和视频格式后，页面上已经有两个文件框：不带 `multiple` 的是封面，带 `multiple` 的是视频。用本机中转（[uploads.md](../../ship-my-game/references/uploads.md) 第 3 种方法）直接放文件，不用截 `click()`。
  - 封面放进去后提示「上传成功」并出缩略图；视频几秒后出播放器。
  - 点「提交」跳回列表，新的一行状态是「审核中」，「本周可上传 N 套素材」少 1。
  - 被驳回的那一行状态是「审核未通过」，操作栏只有「删除」，没有重新提交的入口。改好后按上面的步骤再传一套，照样占本周一个名额。
- 这些提交都没有要求扫码。

**审核结果** `[实测]`
- 结果发到「通知中心」（路径见 [console.md](console.md#读后台的技巧)），一项一条：
  - 游戏简介、推广文案、通用素材封面：「素材配置审核结果」，正文「经平台审核，你的小游戏《<名称>》素材配置已通过审核」；
  - 竖版、横版推广图：「宣传图审核结果」，正文「…宣传图 已通过审核」；
