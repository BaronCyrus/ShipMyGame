# 上传、提审、发布

**实测情况**（2026-11-07，个人主体的单机小游戏，从上传一直走到发布上线）
- 第一次提审约 3 小时后被驳回：Unity 6 包第一次打开黑屏（见「被拒或卡住」和 [build.md](build.md) 第 10 节 B7）。
- 修好后重新上传、选为体验版、请用户在手机上核对，再提审，约 1 小时通过。
- 审核通过 7 分钟后，用户点「提交发布」并扫码确认，线上版本就有了。这时小程序备案刚过平台初审，还没有备案号。
- 除了标 `[实测]` 的地方，下面都是 `[官方]` 依据。还没实测的有：命令行上传、灰度发布、联网游戏的发布条件。走到这里时要逐字读页面，页面和本文不一致就以页面为准，并记进进度档案的「与 skill 不符」。

## 上传开发版本

**上传前检查**
- 用本次要提交的代码重新导出一次，见 [build.md](build.md)。
- 主页显示后台注册的名称；没有「优化建议」弹窗；没有打不开的外链。
- 广告位 ID 可以先空着：流量主要上线以后才能开通，见 [capabilities.md](capabilities.md#广告流量主)。

**方式一：开发者工具上传** `[实测]`（[协同工作和发布](https://developers.weixin.qq.com/miniprogram/dev/framework/quickstart/release.html)）
1. 点工具栏的「上传」，「工具」菜单里也有。
2. 先弹出提示「需要联系管理员……设置为体验版本」，点「确定」。
3. 填「版本号」（例如 `1.0.0`）和「项目备注」（一句话写本版改了什么），点「上传」。实测 14MB 左右的包约 16 秒传完，提示「代码上传成功」。
4. 到后台「版本管理 → 开发版本」核对版本号和项目备注。
- 用桌面操作工具时：工具栏按钮在辅助功能树里找不到，要按截图坐标点；上传窗口的两个输入框要先点一下才找得到 `[实测]`。

**方式二：命令行**（不用打开开发者工具）
- `node scripts/wx_ci.js upload ...`，需要上传密钥，见 [automation.md](automation.md)。
- 这个脚本**未实测**。

**规则**
- 原文：「开发版本只保留每人最新的一份上传的代码」，开发版本可以删除。实测同一个人再上传后，开发版本里只剩新的那份 `[实测]`。
- 用 miniprogram-ci 时，每个机器人编号（1～30）是不是各占一份「每人最新一份」，**未确认**。

## 体验版

1. 在「版本管理 → 开发版本」这个版本的右边，点「提交审核」旁的下拉箭头，选「选为体验版本」。弹出「体验版设置」，页面路径留空即可，点「提交」 `[实测]`。每个小游戏只能有一个体验版 `[官方]`（[代码包](https://developers.weixin.qq.com/minigame/dev/guide/base-ability/code-package.html)）。
2. 版本号下面出现「体验版」标记，点旁边的二维码图标就能打开体验版码。原文：「二维码已设定有效期限，每次查看时将更新时效」，实测有效期 7 天 `[实测]`。
3. 管理员本人可以直接扫体验版二维码。其他人要先在「成员管理 → 体验成员」里加上，或者用 miniprogram-mp-ci 批量添加，见 [automation.md](automation.md#体验成员)。
4. 请用户用体验版把 [build.md 的真机清单](build.md#真机验证清单) 再走一遍。这是提审前的最后一次核对。

## 提交审核表单

**前置条件**（全部满足再进入提审闸门）
- 适龄提示已提交，最好已通过，见 [console.md](console.md#适龄提示)。
- 用户隐私保护指引已完成，见 [console.md](console.md#用户隐私保护指引)。
- 开发版本已上传，体验版已核对过。
- 游戏内显示的名称和后台名称一致，二级类目和游戏内容一致。

**打开表单** `[实测]`
1. 「版本管理 → 开发版本」，在要提交的版本上点「提交审核」。
2. 弹出「提交审核的相关须知」：勾选「已阅读并了解平台审核规则」，点「下一步」。
3. 表单在新标签页打开，嵌在 game.weixin.qq.com 的跨域 iframe 里。find、read_page 和页面脚本都读不到它，只能截图、按坐标点和打字。

**表单字段** `[实测]`（第二次提审时逐项读的；第一次填过的值会自动带出。依据：[版本审核](https://developers.weixin.qq.com/minigame/introduction/guide/bbsh.html)）

| 区块 | 字段 | 实测情况和取值 |
|---|---|---|
| 基础信息 | 游戏引擎 | 下拉框，选 Unity；用团结引擎的选团结 |
| 基础信息 | 网络类型 | 「单机」或「联网」，和小游戏备案时选的一致。页面原文：单机是「游戏自身功能无需连接网络可独立在本地上运行（游戏防沉迷、广告变现不属于自身游戏功能），上架需要完成小游戏备案」；联网「上架需要完成小程序备案」 |
| 基础信息 | 《单机承诺函》 | 选单机时显示已签署的缩略图（小游戏备案第 1 步签过这份文件） |
| 用户隐私保护指引设置 | 当前状态 | 要显示「已完善」，旁边是「修改协议」「刷新状态」 |
| 适龄提示设置 | 当前状态 | 要显示「已设置」，旁边是「去设置」「刷新状态」 |
| 版本更新说明 | 多行输入框，上限 300 字 | 首版写「首个上线版本：<一句话玩法>」，再分条列主要功能、适龄提示、单机和存档方式；修复了驳回问题的版本，加一句修了什么。实测写了 217 字 |
| 版本更新提醒（选填） | 版本更新内容、版本更新信息（限 15 字） | 还没有订阅用户时下拉框是灰的，留空 |
| 宣传图（选填） | 横版推广图、竖版推广图 | 实测没传也通过了 |
| 开发者信息 | 苹果开发者账号 | 原文：「苹果开发者账号为必填项（可以填写邮箱地址），苹果开发者信息非必填项」。第一次请用户本人填一个愿意公开的邮箱，之后自动带出。进度档案里只写「已填」 |
| 开发者信息 | 苹果开发者信息（选填） | App Store 游戏名称、下载链接、供应商名称、TeamID；没上 App Store 就留空 |

**提交** `[实测]`
1. 走完提审闸门、用户说「提交」后，点表单底部的「提交」。
2. 弹出隐私合规提醒：涉及处理个人信息时参考《小游戏隐私合规开发指南》，「如已完成配置，请忽略」。不处理个人信息的游戏点「继续提交」。
3. 页面显示「提交成功」，下面是「关闭页面」。
4. 回到「版本管理」刷新：审核版本显示这个版本「审核中」，开发版本的「提交审核」按钮变灰。

**代码来源** `[官方]`（[常见问题](https://developers.weixin.qq.com/minigame/introduction/guide/faq.html)）
- 用了别人授权的代码时，要在「设置 → 游戏设置 → 代码授权管理」完成授权。
- 用了开源库时，可以在「版本更新说明」里写明公共库信息。
- 微信 Unity SDK 本身是官方插件，一般不用说明（推断）。

## 提审闸门

按总入口的提审闸门规则执行。列给用户的内容：
- 渠道：微信小游戏。
- 版本号，以及开发者工具或 miniprogram-ci 报告的代码包大小。
- 版本更新说明的全文。
- 隐私声明：例如单机、未处理任何用户信息。
- 广告：本版有没有接广告，广告位 ID 是不是空的。
- 适龄等级。
- 预计时长：官方写正常 1 个自然日，实测当天就出结果（见下一节）。审核通过后能不能马上发布，要看网络类型，见「发布」。

用户说「提交」后点表单的「提交」，再读「版本管理」确认「审核版本」显示审核中。

## 审核时长和加急 `[官方]`

- 正常情况 1 个自然日。
- 实测（同一天，周六）：第一次提审约 3 小时后被驳回，第二次约 1 小时通过。结果都以「通知中心」的「代码发布审核结果」为准 `[实测]`。
- 加急要同时满足三个条件：
  1. 不是首个版本；
  2. 本季度还有加急次数：每季度 2 次，1、4、7、10 月的 1 日刷新，过期不累计；
  3. 累计注册用户超过 5000。
- 所以首版不能加急。
- 不能用接口提交审核：官方提审接口只给第三方平台用，而且对小游戏返回 `87006 小游戏不能提交`。见 [automation.md](automation.md#不能自动化的环节)。

## 发布

1. 审核通过后，「通知中心」收到「代码发布审核结果」，正文是「经平台审核，你的小游戏《<名称>》已通过审核」。「版本管理 → 审核版本」显示「审核通过待发布」，右边是「提交发布」按钮 `[实测]`。
2. 先看备案条件，它和网络类型有关：
   - 提审表单原文：单机「上架需要完成小游戏备案」，联网「上架需要完成小程序备案」。
   - 官方指引原文：「版本审核通过后，需在 "小程序备案" 完成后，方可发布」 `[官方]`。
   - 实测（单机）：小游戏备案已通过、小程序备案刚过平台初审还没有备案号时，「提交发布」没有被拦，扫码确认后就上线了 `[实测]`。联网游戏没实测过，按官方等备案号。
   - 版本管理页里藏着一个「需完成备案」弹窗，原文「小程序需通过备案审核才可上架，审核时效预计为2-22个工作日……」，按钮「立即备案」。用 get_page_text 读这一页会读到这段字，不代表它弹出来了 `[实测]`。
   - 想在点之前确认：从页面脚本看，点「提交发布」时 VersionManager 组件的 `cgiData.need_beian_to_submit` 为真才弹这个窗，可以先读这个字段。实测单机首版时没有这个字段，也确实没弹。页面改版后这个办法可能失效。
3. 发布前同样先问用户，或者请用户自己点。发布要管理员用微信扫码确认 `[实测]`。发布方式：
   - 全量发布：所有用户都用新版本。
   - 分阶段发布（灰度）：在「提交发布」里选按比例，或者按微信号白名单灰度，白名单最多 100 人。原文：「灰度版无法取消发布、请谨慎使用」（[游戏灰度](https://developers.weixin.qq.com/minigame/dev/guide/base-ability/code-beta.html)）。实测首版发布时，页面数据里的发布方式只有「全量发布」「按微信号灰度」两项。
4. 发布后，「线上版本」显示版本号、发布时间和项目备注，「审核版本」变成「你暂无提交审核的版本或者版本已发布上线」 `[实测]`。在进度档案里记下发布时间和版本号。用户从微信搜索或分享卡片进入，玩到的就是线上版本。

## 被拒或卡住

| 现象 | 怎么办 |
|---|---|
| 版本审核被驳回 | 驳回原因在后台「通知中心」的站内信里，「版本管理」的版本详情里没有 `[实测]`。读原文和违规图示，记进进度档案。按原因改代码或资料，重新上传开发版本，再提审。常见原因：二级类目和内容不符；名称或截图和游戏不一致；广告遮挡「开始/继续游戏」或诱导误点（运营规范 3.2.10）；诱导分享（运营规范 2.5.1）。见 [运营规范](https://developers.weixin.qq.com/minigame/product/) |
| 驳回原因是「需是一个完成品，要求可以打开、可以运行」，违规图示整屏黑、只剩右上角胶囊，标注「游戏卡在此界面无法进一步游戏」 `[实测]` | 审核员用新设备第一次打开就黑屏。Unity 6 包是 B7 的问题，见 [build.md](build.md) 第 10 节。处理顺序：用当前的 `ShipWeChatBuild.cs` 重新导出，日志里要有 `[Ship] B7`；在模拟器里复现第一次打开，确认先出加载页再进主页；上传新的开发版本，设为体验版；请用户在手机上删掉「最近使用」里的这个小游戏，再扫体验版码确认能玩；最后提审，版本更新说明写上「修复首次加载黑屏」 |
| 「提交审核」按钮是灰的 | 先查适龄提示、隐私保护指引、开发版本是否都已完成。实测时，前面的备案没完成前，流程指引页的「版本提审」也是灰的 |
| 审核已通过，点「提交发布」弹出「需完成备案」 | 后台要求先完成小程序备案：等备案号下来再发布，见 [filing.md](filing.md#小程序备案icp)。单机游戏实测没有被拦，见上面「发布」 |
| 小游戏备案被驳回 | 见 [filing.md](filing.md#小游戏备案) 的「常见驳回原因」 |
| 资质被驳回 | 见 [filing.md](filing.md#资质提交) |
| 等了很久没结果 | 到流程指引页看状态，用户也会收到站内信。超过官方时长时，可以通过后台右下角的「开发者助手」转人工查询（官方备案指引的说法） |

需要提审后的结果时：读「版本管理」页和「通知中心」，把结论写进进度档案。
