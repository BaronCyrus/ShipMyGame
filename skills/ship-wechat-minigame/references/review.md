## 上传开发版本

**上传前检查**
- 用本次要提交的代码重新导出一次，见 [build.md](build.md)。
- 主页显示后台注册的名称；没有「优化建议」弹窗；没有打不开的外链。
- 广告位 ID 可以先空着：流量主要上线以后才能开通，见 [capabilities.md](capabilities.md#广告流量主)。

**方式一：开发者工具上传** `[官方]`（[协同工作和发布](https://developers.weixin.qq.com/miniprogram/dev/framework/quickstart/release.html)）
1. 点工具栏的「上传」，「工具」菜单里也有。
2. 填「版本号」（例如 `1.0.0`）和「项目备注」（一句话写本版改了什么）。
3. 上传完，到后台「版本管理 → 开发版本」核对。

**方式二：命令行**（不用打开开发者工具）
- `node scripts/wx_ci.js upload ...`，需要上传密钥，见 [automation.md](automation.md)。
- 这个脚本**未实测**。

**规则**
- 原文：「开发版本只保留每人最新的一份上传的代码」，开发版本可以删除。
- 用 miniprogram-ci 时，每个机器人编号（1～30）是不是各占一份「每人最新一份」，**未确认**。

## 体验版

1. 在「版本管理 → 开发版本」的这个版本上点「选为体验版」，按钮名以页面为准。每个小游戏只能有一个体验版 `[官方]`（[代码包](https://developers.weixin.qq.com/minigame/dev/guide/base-ability/code-package.html)）。
2. 管理员本人可以直接扫体验版二维码。其他人要先在「成员管理 → 体验成员」里加上，或者用 miniprogram-mp-ci 批量添加，见 [automation.md](automation.md#体验成员)。
3. 请用户用体验版把 [build.md 的真机清单](build.md#真机验证清单) 再走一遍。这是提审前的最后一次核对。

## 提交审核表单

**前置条件**（全部满足再进入提审闸门）
- 适龄提示已提交，最好已通过，见 [console.md](console.md#适龄提示)。
- 用户隐私保护指引已完成，见 [console.md](console.md#用户隐私保护指引)。
- 开发版本已上传，体验版已核对过。
- 游戏内显示的名称和后台名称一致，二级类目和游戏内容一致。

**入口**：「版本管理 → 开发版本」，在要提交的版本上点「提交审核」。

**要填的内容** `[官方]`（[版本审核](https://developers.weixin.qq.com/minigame/introduction/guide/bbsh.html)）
表单要先有开发版本才能看到，字段本仓库**还没有在后台核对过**。

| 步骤 | 字段 | 取值 |
|---|---|---|
| 1 | 游戏开发对应的引擎 | 选 Unity；用团结引擎的选团结 |
| 2 | 用户隐私保护指引 | 已在基本设置完成的，这里确认即可 |
| 3 | 适龄提示设置 | 同上 |
| 4 | 版本更新说明 | 首版写「首个版本：<一句话玩法>」 |
| 5 | 上传宣传图 | 非必填 |
| 6 | 开发者信息 | 原文：「苹果开发者账号为必填项（可以填写邮箱地址），苹果开发者信息非必填项」。填用户同意公开的邮箱，进度档案里只写「已填」 |
| 7 | 提交 | 走提审闸门 |

**代码来源** `[官方]`（[常见问题](https://developers.weixin.qq.com/minigame/introduction/guide/faq.html)）
- 用了别人授权的代码时，要在「设置 → 游戏设置 → 代码授权管理」完成授权。
- 用了开源库时，可以在「版本更新说明」里写明公共库信息。
- 微信 Unity SDK 本身是官方插件，一般不用说明（推断）。

## 提审闸门

按总入口的提审闸门规则执行。列给用户的内容：
- 渠道：微信小游戏。
- 版本号，以及开发者工具或 miniprogram-ci 报告的代码包大小。
- 版本更新说明的全文。
- 隐私声明：例如单机、未处理任何用户信息。
- 广告：本版有没有接广告，广告位 ID 是不是空的。
- 适龄等级。
- 预计时长：审核正常 1 个自然日；审核通过后，还要等小程序备案拿到备案号才能发布。

用户说「提交」后点「提交审核」，再读页面确认「审核版本」显示审核中。

## 审核时长和加急 `[官方]`

- 正常情况 1 个自然日。
- 加急要同时满足三个条件：
  1. 不是首个版本；
  2. 本季度还有加急次数：每季度 2 次，1、4、7、10 月的 1 日刷新，过期不累计；
  3. 累计注册用户超过 5000。
- 所以首版不能加急。
- 不能用接口提交审核：官方提审接口只给第三方平台用，而且对小游戏返回 `87006 小游戏不能提交`。见 [automation.md](automation.md#不能自动化的环节)。

## 发布 `[官方]`

1. 审核通过后，管理员微信会收到通知。在「版本管理 → 审核版本」能看到通过的版本。
2. **要等小程序备案拿到备案号才能发布**。原文：「版本审核通过后，需在 "小程序备案" 完成后，方可发布」。
3. 点「发布」之前同样先问用户。可以选：
   - 全量发布：所有用户都用新版本。
   - 分阶段发布（灰度）：在「提交发布」里选按比例，或者按微信号白名单灰度，白名单最多 100 人。原文：「灰度版无法取消发布、请谨慎使用」（[游戏灰度](https://developers.weixin.qq.com/minigame/dev/guide/base-ability/code-beta.html)）。
4. 发布后，用户从微信搜索或分享卡片进入，玩到的就是线上版本。在进度档案里记下发布时间和版本号。

## 被拒或卡住

| 现象 | 怎么办 |
|---|---|
| 版本审核被驳回 | 读驳回原因的原文，记进进度档案。按原因改代码或资料，重新上传开发版本，再提审。常见原因：二级类目和内容不符；名称或截图和游戏不一致；广告遮挡「开始/继续游戏」或诱导误点（运营规范 3.2.10）；诱导分享（运营规范 2.5.1）。见 [运营规范](https://developers.weixin.qq.com/minigame/product/) |
| 「提交审核」按钮是灰的 | 先查适龄提示、隐私保护指引、开发版本是否都已完成。实测时，前面的备案没完成前，流程指引页的「版本提审」也是灰的 |
| 审核已通过但不能发布 | 小程序备案还没拿到备案号，见 [filing.md](filing.md#小程序备案icp) |
| 小游戏备案被驳回 | 见 [filing.md](filing.md#小游戏备案) 的「常见驳回原因」 |
| 资质被驳回 | 见 [filing.md](filing.md#资质提交) |
| 等了很久没结果 | 到流程指引页看状态，用户也会收到站内信。超过官方时长时，可以通过后台右下角的「开发者助手」转人工查询（官方备案指引的说法） |

需要提审后的结果时：读「版本管理」页和「通知中心」，把结论写进进度档案。
